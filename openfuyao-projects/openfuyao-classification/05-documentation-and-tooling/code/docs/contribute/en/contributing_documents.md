# Contributing Documents

The openFuyao community welcomes you to contribute documents. We encourage developers to participate in document feedback and contribution in various ways. You can contribute to the **docs** repositories through channels such as reporting document issues, rectifying document defects, and reviewing modified content.

## Content Copyright

- The content and images you submit must be original and must not infringe others' intellectual property rights.

- openFuyao has the right to modify your submitted content according to relevant specifications.

## Preparing the Environment

Before modifying document content, you need to have a GitCode account with the CLA signing permission and a local Git tool. You need to perform the following operations:

- Prepare your own GitCode account.
- Sign the CLA.
- To modify multiple files in batches, install and configure Git.

For details, see [Development Environment Preparation](https://gitcode.com/openFuyao/openfuyao-website/blob/master/app/zh/blogs/blogsList/Getting_Started_with_openFuyao_Open_Source_Community/index.md#development-environment-preparation).

## Contribution Methods

### Reporting Document Issues

High-quality feedback helps us continuously improve the content and quality of documents. The more detailed the information you provide, the more helpful it is for us to solve issues.

1. On the GitCode page, click **+ New Issue** on the **Issues** tab page and add the issue description.

2. Click **Create Issue** to submit the issue. Wait for the document team members to confirm the issue.

   For details, see [Create an Issue](https://docs.gitcode.com/en/docs/help/home/org_project/issue/create_issue).

> **NOTE**: **How do I report a high-quality issue?**
>
> - Provide a clear description of the issue, specifying the exact missing, outdated, or incorrect content, or text that needs improvement.
> - Explain the impact of the issue on users.
> - Limit the scope of the given issue to specific content or a specific task. If the issue involves a large domain, you can divide it into multiple small issues. For example, "The document needs to be optimized" is a vague expression, while "The *XX* User Guide lacks a description of the *XXX* step" is specific and actionable.
> - Search existing issues to check if any related or similar issues have already been recorded.
> - If the new issue is associated with another issue or PR, reference it using its full URL or the PR number prefixed with a number sign (#).

### Modifying Documents

#### Using a Web IDE

Directly modify Markdown files on the web page, enabling quick editing and fixing for existing documents. This method is suitable for minor content modifications and supplementation.

1. Click ![](./figures/webide.png) in the upper right corner of the document page to go to the source file page of the GitCode project.

2. On the source file page, make changes or fixes directly in the relevant content.

3. After the modification is complete, submit the code to complete the contribution.

   For details, see [Lightweight Pull Request](https://docs.gitcode.com/en/docs/help/home/org_project/pullrequests/pr-lightweight) in GitCode Help Docs.

#### Modifying Documents in Git Mode

This method is applicable to scenarios where a large number of documents need to be modified or added. For example, it can be used for making changes or additions to documents related to new features.

1. Fork the code repository to your personal repository.
2. Create a feature branch.
3. Submit code changes.
4. Create a PR.
5. Participate in code review.

For details, see [Fork Workflow](https://docs.gitcode.com/en/docs/help/home/org_project/pullrequests/pr-fork) in GitCode Help Docs.

Document team members will review and merge your changes. Thank you for your contribution to openFuyao documents.
