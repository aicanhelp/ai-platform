# **开发指南

## 特性介绍

*必选。开篇先阐明what、why、when（是什么？为什么要用它？能解决什么问题或带来哪些效益？）基础信息，让开发者对方案/特性/功能/模块有初步认知。*
*此处可以复制用户指南中特性介绍的短描述内容。再补充：详情请参见[特性用户指南]。*

## 约束与限制

*必选。我要使用该方案/特性/功能/模块，有什么约束条件吗*？*该方案/特性/功能/模块实现的程度如何，能满足我的需求吗？*

*eg：功能限制（明确不支持的场景、规格限制）*

​       *操作限制（已知问题的操作、潜在风险的操作（如引起性能降低））*

## 环境准备

### 环境要求

*必选。*

### 搭建环境

*必选。*

### 检验环境是否搭建成功

*必选。根据具体开发场景分析分解，可同开发步骤就近放置。*

*明确如何准备开发环境（如软硬件配置要求、工具要求、设备要求等）*

## xxx特性概述

*可选。当x方案/特性/功能/模块的任务场景、场景间关系不是显性呈现的信息，且这些信息不适合直接放入开篇“xxx简介”时，需要提供本节，用于承载：任务场景概况（任务场景划分维度等）、场景间关系介绍（何时选择各场景）等。*

*如果该开发场景相对简单，可以不提供本节。*

## 使用场景（使用具体任务或场景名称代替）

*必选。开发者需要通过那些操作来达成开发目标，这就是使用场景。*

*开发场景可以有1个或多个，可按需添加多个开发指导章节。同时按照分层逻辑即大场景->小场景->任务逻辑（对应“开发流程”）->操作步骤。*

### 使用场景概述

*必选。用于承载使用场景直接相关的概述内容。*

### 系统架构
*必选。从全局的角度出发，描述整个系统的组成、各个相关组件之间的关系、以及它们如何协同工作。更专注系统的逻辑架构，不涉及具体的实现细节。目的是帮助开发者理解系统的整体设计思路，确定各个模块的职责和边界。*

### 开发流程

*可选。当开发步骤较多（达到**5步以上**核心操作）或步骤间存在复杂的逻辑关系时，请提供开发流程，让开发者对他要执行的操作有一个全景认知。*

*一般使用流程图、表。*

### 接口说明

*必选。在开发步骤中涉及哪些关键接口，且提供接口简介。*

*如果接口超过10个，只提供主要接口即可。*

*接口及其涉及的功能必须在文档发布时对应版本已支持。*

*eg：*

| *接口名* | *描述*         |
| -------- | -------------- |
| *xxx*    | *查询安装组件* |

### 开发步骤

*必选。*

*描述开发的完整过程，不可遗漏关键配置步骤。*

*文档中的片段示例代码直接拷贝进DevEco Studio中，放入上下文可以正常编译。并且执行结果和文档描述一致。*

*每个步骤要有清晰的执行主体，明确操作目的、操作内容、场景。使用祈使句描述步骤。*

*步骤中如果涉及接口调用，需要给出使用的接口及使用说明、示例代码。*

*关键步骤可放置示例代码中有开发建议或注意事项的位置，需要提供相关描述（示例代码中采用注释）。*

-    *必要的补充说明随开发步骤就近放置：可能存在的特殊操作、操作权限要求、效率提升技巧、简单背景知识等。*

- *用户需要注意的信息需要事先告知：对其他功能可能造成影响的操作、对系统性能、可靠性可能造成影响的操作、可能导致丢失数据或者各类安全问题的操作。这些信息需要在“操作步骤”之前，以区别于正文的样式加以提示强调。*

### 调测验证

*必选。*

*开发完成后，如有独立的调测验证操作，需提供指导。操作步骤要求同“开发步骤”。*

*此处仅提供最后的业务调测，每个小任务的操作结果，推荐在开发步骤执行完成后及时验证。*
