# 社区协同测试

## 定位

社区协同测试是针对openFuyao社区RC版本的测试，是各社区伙伴在QA-SIG基本测试工作基础上，针对自身使用特性与场景进行的测试。

## 协同测试目标

核心目标：在多样化算力环境中保障openFuyao社区发行版的特性质量。

> 单一的测试环境对特性质量的保障往往是有限的，社区对测试的共同投入能够从客观上提高测试场景覆盖。

对openFuyao本身，社区协同测试旨在：

1. 保障功能可用性，通过社区伙伴的贡献增加系统级集成测试的场景，验证在实际使用场景下的可用性。
2. 明确特性兼容性，针对社区伙伴重点关注的环境开展兼容性测试，完善openFuyao的环境兼容信息说明。
3. 增强特性DFX保障能力，在社区测试中收集特性优化需求，提高特性使用易用性的同时，增强开发过程中的问题可定位性。

此外，社区协同测试也能够让社区伙伴：

1. 在RC版本阶段提前体验openFuyao版本特性，允许社区伙伴代表客户对openFuyao进行验收；
2. 通过协同测试，验证伙伴自用或商用场景，确保openFuyao社区发行版测试场景完整、特性质量满足伙伴实际使用要求；
3. 通过社区分工协作，提高测试效率，加快商业发行版推出节奏。

## 协同测试职责与要求

职责划分：
- 特性SIG：负责SIG相关特性的功能测试，与包含性能测试在内的部分专项测试。
- QA-SIG：负责社区基础规格测试，如专项测试和系统级集成测试任务。
- 社区伙伴：负责针对自身关注特性与需求场景的增强测试与补充测试。

此外，协同测试活动需跟随openFuyao社区的RC版本发布节奏；完成后，需将测试问题以issue形式提交，并在QA-SIG进行测试结果评审与归档。

## 协同测试输出件

1. 协同测试报告；
2. 测试Issue。

## 协同测试工作指南

### 流程规范

1. issue管理流程：提交规范（issue类型、优先级、标签、信息关联等）、问题回归与issue状态变更流程
2. 特性转测管理：特性转测节奏指定、转测标准、验收与打回标准等
3. 测试工作流指导：从测试策略评审、测试用例执行、测试报告输出到最终测试报告评审

### 开发、测试指南

1. 自动化测试框架指南：针对社区使用的测试框架（Ginkgo、Playwright）提供开发者快速入门，明确社区内测试编写规范
2. 测试工具使用指南：针对社区内使用的自研或第三方测试工具，提供使用指导
