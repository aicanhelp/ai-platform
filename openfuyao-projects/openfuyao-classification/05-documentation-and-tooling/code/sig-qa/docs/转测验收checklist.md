# 转测验收规范 Checklist

**核心原则：原子性，可重复性，可追溯性，完整性，独立性**

| 名称 | 要求 | 检查项 | 规则描述 | 典型问题 |
| :--- | :--- | :--- | :--- | :--- |
| **验收答复时间** | 必须 | 小于等于7天 | 【规则】以转测邮件时间（dd:mm:ss）为准7天内答复 | |
| **可测试性** | 必须 | 是否可测试 | 【规则】若未提供测试性手段导致不具备可测试性，不能转测，转测不通过，环境问题或硬件问题无法解决需要澄清 | |
| | 必须 | 遗留问题 | 【规则】无阻塞后续测试流程的issue遗留 | |
| **冒烟测试** | 必须 | 基线用例全部通过 | 【规则】基线测试用例全部通过，以自动化日构建结果为准 | |
| **流水线检查** | 必须 | 社区门禁 | 【规则】license检查、基本信息检查、接口变更检查、敏感信息检查均通过 | |
| | 必须 | UT覆盖率 | 【规则】目前以各自代码仓流水线要求为准 | |
| | 必须 | 静态检查 | 【规则】代码规范检查、合规检查、安全检查，提示级别以上问题清零 | |
| | 必须 | 编译错误 | 【规则】满足64位编程规范和基本质量要求，无编译错误 | |
| | 必须 | 开源义务履行 | 【规则】NOTICE文件、SCA合规，sca扫描通过 | |
| **转测范围** | 必须 | 交付件检查 | 【规则】提供交付件清单、未交付件清单及未交付件未交付说明，需要完成归档 | |
| **安装部署** | 必须 | 基于社区安装 | 【规则】必须可以基于社区安装部署要求通过验证，建议写入P0用例 | |
| | 建议 | 独立部署 | 【规则】规格内支持独立部署则需要完成此项，建议写入P0用例 | |
| **需求管理** | 必须 | 继承需求清单 | 【规则】提供社区继承需求完整清单；完成社区继承需求开发自检，需要完成归档 | |
| | 必须 | 新增需求清单 | 【规则】提供社区新增需求完整清单；完成社区新增需求开发自检，需要完成归档 | |
| | 必须 | 关联版本的软件变化清单 | 【规则】提供完整的与上个关联版本的软件变化清单（新增/升降级/删除/发布位置变更及原因），需要完成归档 | |
| | 必须 | 转测版本的软件变化清单 | 【规则】提供完整的与上个转测版本的软件变化清单（新增/升降级/删除/发布位置变更及原因），需要完成归档 | |
| **测试用例评审结果** | 必须 | 评审结果 | 【规则】评审结果必须通过 | |
| | 必须 | 评审遗留问题 | 【规则】遗留问题闭环或完成澄清 | |
| **测试用例自动化** | 必须 | 自动化完成时间 | 【规则】max（5个工作日，7个自然日） | |
| | 必须 | P0级用例自动化完成100% | 【规则】P0级测试用例全部通过，建议以自动化日构建结果为准，无法上日构建的需说明原因并提供自验结果，需要截图至测试用例表归档 | |
| | 必须 | P1级用例自动化完成70% | 【规则】P1级测试用例要求完成70%以上，建议完成100%，未完成需声明原因。 | |
| **开发自提单检查** | 必须 | 转测邮件中的issue要在代码仓提交 | | |
| **其他** | | | | |
| **自动化后续跟进** | 必须 | 总体自动化率>80% | 测试后续跟进整体自动化完成情况 | |
| **用例归档** | 必须 | 归档到QA和用例总表 | 自动化信息补充后，完成用例归档 | |
