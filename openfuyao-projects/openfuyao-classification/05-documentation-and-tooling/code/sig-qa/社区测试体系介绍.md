# 社区测试体系介绍

社区依据需求规格，对特性和社区发行版进行基础测试保障，在此基础上，社区伙伴可针对自用或商用场景，对关注特性进行重点测试加固，或更广泛的测试场景覆盖，进行[社区协同测试](https://gitcode.com/openFuyao/sig-qa/blob/master/docs/%E7%A4%BE%E5%8C%BA%E5%8D%8F%E5%90%8C%E6%B5%8B%E8%AF%95%E6%8C%87%E5%8D%97.md)。

## 参与测试的社区角色
- 特性SIG
- QA SIG
- Infra SIG
- 社区伙伴

## 测试工作职责划分

特性SIG负责UT、DT等特性功能测试、特性级集成测试，及部分特性专项测试； QA SIG负责openFuyao社区发行版的系统级集成测试，并对特性专项测试提供支持；Infra SIG负责门禁类测试的配置工作。

### 特性功能测试

参与角色：特性SIG

职责范围：特性功能的测试，需在IDE或简单Mock环境中确保特性单元功能的正确，以开发者测试为主，如单元测试、API测试。

### 特性级集成测试

参与角色：特性SIG与社区伙伴

职责范围：特性所属各模块间的集成测试，需在实际环境中确保特性各模块能够正确集成并实现需求。

### 特性专项测试

参与角色：QA-SIG与特性SIG

职责范围：
- 性能测试：特性SIG需针对特性的业务性能指标进行性能测试方案设计，并提供性能测试报告；QA-SIG需对特性在系统中集成时的通用指标（如安装部署时间、资源占用情况、接口时延等）进行性能测试，提供性能测试结果。
- 安全测试：QA-SIG需按安全SIG规范进行特性的安全测试；
- 兼容性测试：QA-SIG需对特性与OS、硬件设备、openFuyao社区发行版等不同环境的兼容性进行测试；
- 长稳测试：QA-SIG需对报名参与长稳的孵化期特性、全部成熟期特性进行7 * 24h的长稳测试；
- 资料测试：由QA-SIG承担。
- 一致性测试：QA-SIG负责一致性测试的执行与用例管理，容器平台SIG及其他特性SIG负责一致性用例的维护。

### 系统级集成测试

参与角色：QA-SIG与社区伙伴

职责范围：openFuyao社区发行版与版本特性在不同场景下的集成验证。与特性级集成测试的功能验证相比，更注重在各类场景下系统的稳定性、可用性等。

除QA-SIG负责openFuyao社区保障的场景外，社区伙伴可以在该环节中根据需求扩充系统集成测试场景，使用或构建社区实验室环境，并进行相应的系统集成测试，输出报告并归档至QA-SIG。

### 门禁类测试

参与角色：Infra SIG和特性SIG

职责范围：license检查、基本信息检查、接口变更检查、敏感信息检查等。

开发者通过PR的方式将对软件包的修改提交后，CI工程会自动触发门禁类检查，当门禁类检查通过后进行镜像的编译构建，并发布**daily build版本**。各项目的maintainer需要对门禁检查结果进行检查。

### 特性-QA接口人

在社区协同测试过程中，根据测试工作类型不同，需要特性SIG与QA-SIG不同程度的参与与协作。QA-SIG作为社区协同测试的整体负责方，各特性SIG设置**QA-SIG接口人**，负责特性SIG与QA-SIG间的沟通。

QA-SIG接口人需要对所属SIG的相关测试项任务负责：
- 对SIG内：看护各细粒度测试任务的规划与进度，跟踪特性转测进展。
- 对QA-SIG：定期汇报测试任务规划与进展。

该接口人的设置有以下需求或特点：
- 该人员需要对SIG内各测试工作项有全局的了解，但并不要求其本身是具体测试工作的执行者；
- 可以是该SIG的成员，也可以是QA-SIG的成员；
- 该接口人的设置应当相对稳定，至少能够完整覆盖某一版本时间跨度；

各SIG组（特性、专题）应当能提供相对稳定的QA-SIG接口人，对该SIG的特性相关测试项任务负责：对SIG内需看护各细粒度测试任务的进度、转测进展，对QA-SIG汇报测试任务进展。该接口人可以是该SIG的成员，也可以是QA-SIG的成员。

## 社区测试流程

社区测试随版本节奏进行，一般有以下阶段：
- 特性
  - 特性自测阶段：特性在开发过程中进行开发者自测；
  - 特性转测验收阶段：特性需求开发完成，执行自动化功能测试与集成测试并通过全部P0/P1用例，即通过转测验收；特性转测验收时间由特性SIG决策。
  - 特性集成测试阶段：特性需求开发完成，执行自动化功能测试与集成测试并通过全部用例，即通过集成测试；
- 版本
  - 联调测试阶段：社区定期发布RC联调版本，供社区伙伴进行特性试用与联调验证。RC版本发布时间由Release-Management SIG决定。
  - 版本发布测试：版本发布前进行的更高要求测试，包含全部特性级测试内容的同时，执行系统级集成测试。
