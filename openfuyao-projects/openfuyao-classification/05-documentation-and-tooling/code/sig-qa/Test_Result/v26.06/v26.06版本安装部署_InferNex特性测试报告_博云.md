# openFuyao 26.6.0-rc.2 InferNex & 安装部署测试报告

> Author: 博云

## 1. 背景说明

openFuyao 是一个面向云原生 AI 推理场景的开源容器平台，提供从集群安装部署、AI 推理集成部署（InferNex）、版本生命周期管理到虚拟化（KubeVirt）等端到端能力。

本次测试聚焦以下三个核心特性：
- **InferNex 集成部署（x86 环境）**：验证 AI 推理套件在 x86_64 架构下的 Helm 一键部署能力，覆盖组件选装、卸载清理、命名空间配置、可观测组件选装及资料文档验证。
- **InferNex 集成部署（安全最小化）**：验证 InferNex 在安全最小配置（仅 CPU，无 NPU）下的模板渲染、安装卸载、组件检查及推理接口验证。
- **openFuyaoCore 版本生命周期管理**：验证版本配置索引、各版本配置文件完整性、版本演进、集群组件版本一致性、onlineImage 可用性、命名规范及资料文档。

## 2. Goals（目标）

- 验证 InferNex 在 x86_64 环境下的 Helm 部署、组件选装、卸载清理全流程可用性；（RP1）
- 验证 InferNex 在安全最小配置下的部署与组件行为符合预期；（RP1）
- 验证 openFuyaoCore 版本生命周期管理功能完整、版本配置可访问、演进清晰、集群组件版本一致；（RP1）

## 3. Non-Goals（非目标）

- 不涉及 Ascend 910 NPU 环境下的推理功能验证（x86 测试环境无 NPU 设备）
- 不涉及性能测试、长稳测试、安全测试等专项测试
- 不涉及多集群管理面功能验证

## 5. 功能测试

### 5.1 场景一：InferNex x86 集成部署测试

#### 5.1.1 场景描述

在 openEuler 22.03 x86_64 环境下，通过 Helm Chart 部署 InferNex AI 推理套件，覆盖**默认配置部署**和**安全最小化部署**两种模式，验证一键部署、组件选装/禁用、卸载清理、命名空间配置、可观测组件选装、模板渲染、Pod 状态检查、推理接口、Helm 管理及资料文档的可用性。

InferNex 核心组件包括：
- **Hermes-router（智能路由）**：EPP（Envoy Proxy Plugin）负责请求路由决策
- **Inference Backend（推理后端）**：基于 vLLM 的高性能推理引擎（LWS 编排）
- **Cache-indexer**：全局 KVCache 管理器
- **Mooncake**：分布式 KVCache 池化存储
- **Eagle-eye**：推理可观测体系（硬件诊断、硬件监控、网络性能采集）
- **Istio**：开源 API 网关
- **PD-Orchestrator**：弹性扩缩容决策框架（含潮汐算法、RSG）

#### 5.1.4 关键问题分析

**问题 1：hermes-router 镜像 x86 架构兼容性 Bug（阻塞）**

- **现象**：EPP 容器持续 CrashLoopBackOff，日志 `exec /app/epp: exec format error`
- **根因**：`hermes-router:latest` 镜像的 AMD64 manifest 中，`/app/epp` 二进制文件实际为 ARM aarch64 架构编译产物，x86_64 CPU 无法执行
- **影响**：阻塞 x86_64 环境下的 InferNex 完整部署，智能路由功能不可用
- **建议**：修复 hermes-router 镜像的 AMD64 构建流程，确保 `/app/epp` 为 x86_64 二进制

**问题 2：推理接口在无 NPU 环境下阻塞（预期行为）**

- **现象**：推理服务 Service 仅包含 notReady 端点，接口不可访问
- **根因**：当前环境无 Ascend/NPU 资源，推理后端 Pod 无法就绪
- **影响**：CPU-only 模式下推理功能不可用（属预期行为，非 Bug）
- **建议**：文档中明确标注 x86/CPU-only 环境的限制说明

## 7. 测试结论

### 7.1 整体结论

本次测试覆盖了 **InferNex x86 集成部署**（14 个用例，含默认配置和安全最小化两个子场景）和 **openFuyaoCore 版本生命周期管理**（7 个用例），共计 **21 个测试用例**。

- **openFuyaoCore 版本生命周期管理**功能完整可用，版本索引完整、配置可访问、版本演进清晰、集群组件版本与版本配置完全一致、onlineImage 可用，7 个用例全部通过，**通过率 100%**。
- **InferNex x86 集成部署**控制面组件部署基本可用，但存在 1 个阻塞问题（hermes-router 镜像 x86 架构兼容性 Bug）导致智能路由功能不可用。安全最小化部署的 safe values 配置问题已修复，组件启用情况符合预期。整体通过率 71.4%（14 用例：10 通过 / 3 部分通过 / 1 不通过）。

### 7.2 风险提示

1. **高风险**：hermes-router 镜像架构兼容性 Bug 阻塞 x86 环境的 InferNex 完整部署，需在正式发布前修复。
2. **低风险**：文档中缺少 x86 环境限制说明，建议补充。

### 7.3 改进建议

1. **修复 hermes-router 镜像 AMD64 构建**：确保 `/app/epp` 为 x86_64 二进制，通过 CI 增加多架构验证。
2. **文档完善**：在 InferNex 用户指南中补充 x86 架构限制说明、版本升级路径文档。
3. **latest 配置优化**：建议 `latest` 配置中的 `openFuyaoVersion` 字段改为具体版本号，便于版本追溯。
