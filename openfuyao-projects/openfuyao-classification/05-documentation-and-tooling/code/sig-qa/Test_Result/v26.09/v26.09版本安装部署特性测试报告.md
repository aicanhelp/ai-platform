# v26.09-安装部署-特性测试报告

# 1     特性概述

本版本安装部署特性的核心目标是实现集群组件的平滑安装与升级能力增强，通过引入 DAG+YamlInstall 与 HelmInstall 双通道部署机制、统一状态机模型、强化前置检查与异常场景容错，并完成质量加固与安全加固，全面提升安装部署流程的可靠性、可观测性与安全性。

## 1.1 特性清单

| 特性名称 | sig组 | 特性描述 |
| -------- | ---- | -------- |
| [安装部署]集群组件平滑安装和升级：DAG+YamlInstall | sig-installation | 基于 DAG（有向无环图）编排集群组件的安装/升级流程，使用 YamlInstall 方式部署组件，支持依赖关系管理、分阶段执行、失败回滚 |
| [安装部署]集群组件平滑安装和升级：HelmInstall | sig-installation | 基于 Helm Chart 实现集群组件的安装与升级，支持 Helm 语义化版本管理、values 覆盖、release 管理 |
| [安装部署]质量加固 | sig-installation | 针对安装部署流程的质量加固，包括错误处理、日志规范、边界条件覆盖等 |
| 安装部署异常场景优化 | sig-installation | 优化安装部署过程中的异常场景处理，如组件冲突、部分节点失败等场景的容错与恢复 |
| 安装部署前置检查 | sig-installation | 在安装部署前执行环境前置检查（OS 版本、内核参数、端口占用、磁盘空间、依赖组件等），提前发现不满足条件 |
| 安装部署静态pod更新 | sig-installation | 支持静态 Pod（如 etcd、kube-apiserver 等）的更新与重启策略，确保控制面组件平滑更新 |
| 状态机统一 | sig-installation | 统一安装部署各阶段的状态机模型，规范状态流转，提升状态一致性 |
| 安全加固 | sig-installation | 安装部署流程的安全加固，包括镜像签名校验、组件权限最小化、敏感信息加密、默认安全配置等 |

## 3.3   遗留问题分析

### 3.3.1 遗留问题影响以及规避措施

**遗留问题 1：引导节点搭建管理集群过程中bc配置参数存在丢失**

- **问题描述**：在引导节点创建管理集群后，管理集群切换监听自己的bc，此时从引导节点上看到的bc配置参数传递给管理集群上的时候存在丢失，因静态pod热更新与etcd、apiserver、controller-manager、scheduler 的参数强相关，所以此问题会潜在影响管理集群bc配置的自更新能力。

- **影响点**：静态pod更新需求允许通过修改bc参数更新静态pod的参数，但是因为管理集群参数丢失，在修改参数时如果配置了丢失的参数，就会导致集群一直处于更新状态，影响集群正常功能。

- **规避措施**：已验证更新操作超时后可通过重新编辑bc恢复之前的集群状态，并在指导文档中高亮提醒此问题及规避手段。

- **评审结论**：sig-installation及sig-qa评审允许遗留。
