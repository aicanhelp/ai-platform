# openFuyao v26.09 NPU动态池化管理（npu-dra-plugin）特性测试报告

> Author: 广电五舟

## 1. 背景说明

NPU 动态池化管理（npu-dra-plugin）是基于 Kubernetes 原生 DRA（Dynamic Resource Allocation，动态资源分配）架构的昇腾 NPU 深度适配能力，支持以软切分（vNPU）方式按算力/内存配额申请调度昇腾 NPU 资源。

广电五舟作为社区协同测试伙伴，在 v26.09 版本周期内，以"可用性验证"为目标，在 openEuler 22.03 LTS（官方支持 OS）aarch64 虚拟机 NPU 直通环境下，基于 openFuyao v26.06 基础平台部署 npu-dra-driver 0.0.0-latest（26.9.0-rc.1 版本线），验证了平台在线安装、NPU 组件部署、DRA 资源上报与软切分（elastic）vNPU 负载分配的端到端可用性，并从陌生用户视角对安装部署与 DRA 使用文档进行了可用性检验。

### 1.1 特性清单

| ofep编号 | [组件名称]特性名称 | sig组 | 特性描述 |
| -------- | ------------------ | ----- | -------- |
| - | [安装部署]集群组件平滑安装和升级 | sig-installation | bkeadm 快捷下载、bke init 在线安装 openFuyao 平台，业务集群部署 |
| - | [npu-operator]NPU 组件安装部署 | - | 通过 helm 安装 NPU 管理组件 |
| - | [npu_dra_plugin]NPU动态池化管理 | sig-orchestration-engine | 基于 K8s DRA 的昇腾 NPU 适配：DRAConsumableCapacity 特性门控、ResourceSlice/DeviceClass 资源上报、软切分（elastic）vNPU 配额申请与调度 |

## 2. Goals（目标）

- 验证 openEuler 22.03 LTS 虚拟机 NPU 直通环境下的平台在线安装（bkeadm 下载、bke init）与环境准备（磁盘扩容）；
- 验证 npu-operator、npu-dra-driver 组件部署与 DRAConsumableCapacity 特性门控开启；
- 验证 DRA 资源上报（ResourceSlice / DeviceClass）与软切分（elastic）vNPU 负载分配、容器内设备可见性；
- 从陌生用户视角检验安装部署文档与 npu-dra-plugin 用户指南的可用性；

## 3. Non-Goals（非目标）

- 不涉及 x86 环境与物理机环境验证（本次为 aarch64 虚拟机 NPU 直通环境）
- 不涉及性能测试、长稳测试、安全专项测试与资料专项测试
- 不涉及硬切分（hard）、整卡（full）、fixed 等 DeviceClass 模式的深度功能验证（仅验证 DeviceClass 创建）
- 不涉及算力隔离效果的定量验证（仅验证容器内设备识别）

## 7. 测试结论

### 7.1 整体结论

本次协同测试以可用性验证为导向，覆盖**环境准备与平台在线安装**（2 个用例）、**NPU 组件与 DRA 驱动部署**（4 个用例）和**DRA 软切分 vNPU 负载验证**（1 个用例），共计 **7 个用例**：通过 6 个、部分通过 1 个，发现问题 4 个（主要 2、次要 1、建议 1），其中问题 1、2、3 均已解决，问题 4 为文档结构建议。

- **NPU DRA 端到端主流程可用**：npu-operator v26.06 与 npu-dra-driver 0.0.0-latest（26.9.0-rc.1 版本线）安装顺利，DRA 特性门控开启后组件运行正常（npu-dra-plugin / vcannrt-installer Running），ResourceSlice 上报与 5 个 DeviceClass（best-effort/elastic/fixed/full/hard）创建正常；elastic 软切分单 Pod 负载（4Gi/50）分配成功，容器内 npu-smi info 正常识别 310P3 设备，驱动库挂载方案可用。
- **安装部署链路 2 个主要问题已解决**：在线安装默认资源路径 404 导致版本列表获取失败（问题 1）、业务集群 addon 部署阶段 ConfigMap cm.v26.06 缺失（问题 3）均曾直接影响新装环境交付与部署成功率，现已解决。
- **文档持续完善**：bkeadm 配置文档已重构，controlPlaneEndpoint 必填说明已明确（问题 2 已解决）；npu-dra-plugin 指南中构建镜像章节定位仍有优化空间（问题 4 建议）。

### 7.2 约束说明

- DRA 容量记账特性门控默认未开启，需在所有管理节点手工修改 kube-apiserver（DynamicResourceAllocation/DRAConsumableCapacity/DRAAdminAccess）与 kube-scheduler（DynamicResourceAllocation/DRAConsumableCapacity）静态 Pod 配置
- 软切分需在 npu-dra-driver values.yaml 中显式配置节点 NPU（physicalId / vnpuMode: soft / schedulingPolicy: elastic）
- 示例负载需挂载宿主机 Ascend 驱动库（driver/common）、ascend-toolkit 与 npu-smi，并配置 LD_LIBRARY_PATH，方可实现容器内 NPU 识别
