# openFuyao v26.09 InferNex 前置校验（infernex-checker）特性测试报告

> Author: 华鲲振宇

## 1. 背景说明

infernex-checker 是 InferNex AI 推理软件的部署前置依赖校验 CLI 工具，面向 Config-Env（本地配置环境）、K8s（集群状态）、Hardware（昇腾硬件）三层执行只读检测（工具自述 "only detects and reports; does not trigger any deployment operations"，只检测报告、不触发任何部署操作），支持 k8s / config-env / hardware / all 分层执行模式与 `--output` JSON 报告输出，用于在 InferNex 部署前快速定位环境问题。

华鲲振宇作为社区协同测试伙伴，在 v26.09 版本周期内，在客户在用 113 集群（aarch64 / openEuler 22.03 SP4，8×Ascend 910B3）上，使用官方预编译二进制对 infernex-checker 进行了实测：**Config-Env 层、K8s 层与分层执行模式共 10 条用例全部通过**；硬件层（H-01~H-10）因 H-08 慢卡基准耗时较长、被命令超时中断，待后台重跑。

### 1.1 特性清单

| -------- | ------------------ | ----- | -------- |
| 0050 | [infernex-checker]Infernex软件前置依赖校验 | sig-ai-inference | InferNex 部署前置校验 CLI 工具：Config-Env 层（B-01~B-02）、K8s 层（K-01~K-04）、硬件层（H-01~H-10）分层检测，支持 k8s / config-env / hardware / all 模式与 JSON 报告输出，只读不触发部署 |

## 2. Goals（目标）

- 验证 infernex-checker 官方预编译二进制（aarch64）在客户在用集群环境的可用性与检测结果准确性；
- 验证 Config-Env 层校验（B-01 缓存目录、B-02 驱动与镜像 Tag 兼容性），含自然失败场景检测；
- 验证 K8s 层校验（K-01 CoreDNS/DNS 解析、K-02 节点 Ready、K-03 节点无污点、K-04 资源上报）；
- 验证分层执行模式（k8s / config-env 单层模式隔离）与 `--output` JSON 报告输出；
- 识别离线/私有化集群使用时的适配问题（默认 DNS 探针镜像等）；
- （计划）验证硬件层 H-01~H-10 与 all 模式（本轮中断，待重跑）；

## 3. Non-Goals（非目标）

- 不涉及 InferNex 推理平台本体的部署与功能/性能验证（infernex-checker 仅做部署前置校验，只读）
- 不涉及 x86 环境验证（本次为 aarch64 环境）
- 不涉及性能测试、长稳测试、安全专项测试与资料专项测试
- 硬件层 H-01~H-10 与 all 模式验证因超时中断未完成，不在本轮结论范围内（待重跑）
- 不涉及客户集群的清理类变更操作（中断遗留的测试 Pod 按客户集群操作规范未擅自删除）

#### 5.2.4 关键发现：默认 DNS 探针镜像在离线集群不可用（问题 1）

K-01 通过 busybox Pod 探测各节点 DNS。默认探针镜像 `busybox:1.36`（docker.io）在本离线集群无法拉取，导致首次运行 K-01 误报失败（假阴性）并跳过 K8s 层后续检查：

```text
❌ K-01  DNS resolution failed on all nodes: worker
⛔ K8s layer terminated: K-01 failed, skipping subsequent checks
```

实测集群缓存的可用镜像为 `hub.oepkgs.net/openfuyao/busybox:1.36.1`，追加 `--dns-check-image hub.oepkgs.net/openfuyao/busybox:1.36.1` 后 K-01 真实通过（见 5.2.3）。**离线/私有化集群使用 infernex-checker 时务必指定私有 DNS 探针镜像**——详见问题 1。

### 5.4 场景四：硬件层校验（H-01~H-10）——中断，待重跑

#### 5.4.1 场景描述

执行 hardware 模式校验昇腾硬件健康状态（H-01~H-10），其中 H-08 慢卡检测需启动 msprof 基准 Pod（占用 2 个 idle NPU）执行基准测试，耗时较长。

#### 5.4.2 执行情况与待办

- **中断原因**：H-08 慢卡检测基准耗时超过测试人员设置的命令超时（300s），命令被中途杀掉，H-01~H-10 未执行完成。
- **副作用**：遗留 1 个未清理的测试 Pod `default/msprof-slowcard-...`（占用 2 NPU）。因该集群为在用客户集群，按操作规范未擅自删除。
- **待办**：删除遗留 Pod 后，以 nohup 后台方式重跑 hardware 层（跑完自动清理），并完成 all 模式校验（ic_deploy_001 / ic_deploy_003、ic_hw_001~033 等）。

本轮硬件层无有效执行结果，不计入统计。

## 7. 测试结论

### 7.1 整体结论

本次协同测试在客户在用 113 集群（aarch64 / openEuler 22.03 SP4，8×Ascend 910B3，K8s v1.34.3-of.1）上开展，infernex-checker 已执行 **Config-Env 层、K8s 层与分层执行模式共 10 条用例，全部通过（通过率 100%）**，发现问题 3 个（主要 1、次要 1、建议 1），其中问题 1、2 已提交 issue，于下个版本修复。硬件层未完成，本轮为阶段性结果。

- **已执行部分质量良好**：B-01 缓存目录缺失时能自然触发失败并给出可操作修复建议（mkdir -p /home/llm_cache && chmod 755），创建后判定通过；B-02 驱动兼容性判定正确（Driver 25.5.2 ↔ image v0.18.0）；K8s 层四项检查（CoreDNS/DNS、节点 Ready、无污点、资源上报）全部符合预期，K-04 INFO 提示资源充裕（剩余 CPU 189.5 核、内存 ~1.47TiB）；单层模式隔离与 JSON 报告输出均符合预期。
- **重要发现（问题 1）**：离线/私有化集群下默认 DNS 探针镜像 busybox:1.36（docker.io）不可拉取，导致 K-01 假阴性并中断 K8s 层后续检查，必须以 `--dns-check-image` 指定私有镜像规避，建议社区侧优化默认值。
- **完成度受限**：硬件层 H-01~H-10 因 H-08 慢卡基准耗时长被命令超时中断（遗留 1 个 msprof 基准 Pod 占 2 NPU，待清理重跑），待后续补充执行后归档完整结论。

### 7.2 约束说明

- 离线/私有化集群执行 k8s 模式校验必须指定私有 DNS 探针镜像（本集群实测可用：`hub.oepkgs.net/openfuyao/busybox:1.36.1`），否则 K-01 假阴性并跳过后续检查
- 硬件层 H-08 慢卡检测需启动 msprof 基准 Pod（占用 2 个 idle NPU）且耗时较长，建议以 nohup 后台方式执行并放宽超时设置
- 硬件层超时中断会在 default 命名空间遗留 msprof-slowcard-* 测试 Pod（占 2 NPU），重跑前需人工清理
- 本轮验证基于 aarch64 客户在用集群环境，x86 环境结论需复验

### 7.3 风险提示

1. **中风险**：问题 1（默认 DNS 探针镜像假阴性）——离线/私有化集群用户若不熟悉参数配置，会误判集群 DNS 异常并中断 K8s 层校验，直接影响工具在离线交付场景的可用性
2. **低风险**：硬件层中断待重跑，H-01~H-10 与 all 模式结果缺失；遗留 msprof-slowcard Pod 占用 2 NPU 资源，待人工清理

### 7.4 改进建议

1. **默认镜像**：将 DNS 探针默认镜像改为社区仓地址（hub.oepkgs.net/openfuyao/busybox:1.36.1 已实测可用），或在工具输出与文档中显著提示离线集群须配 `--dns-check-image`（已提交 issue，于下个版本修复）
2. **工具健壮性**：硬件层长耗时检查（H-08 msprof 基准）增加耗时预估提示；异常中断时自动清理基准 Pod，避免遗留资源占用（已提交 issue，于下个版本修复）
3. **文档**：补充离线/私有化集群使用说明与必配参数清单

### 7.5 后续测试建议

- 问题 1、2 修复后于下个版本回归验证（DNS 探针默认镜像离线可用性、H-08 基准耗时预估提示与异常中断自动清理）
- 删除遗留 msprof-slowcard Pod 后，以 nohup 后台方式重跑 hardware 层（H-01~H-10）与 all 模式（ic_deploy_001/003、ic_hw_001~033 等）
- 基于第 2 次执行结果（ce2/k8s2 系列）归档证据文件（终端输出 + JSON 报告）
