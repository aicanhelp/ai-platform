# v26.09-FluxSandbox沙箱调度引擎-特性测试报告

# 1     特性概述

FluxSandbox是高性能Kubernetes沙箱调度引擎，作为OpenSandbox的`flux`runtime后端，面向AI Agent工作负载提供低时延、高吞吐的沙箱生命周期管理能力。支持两种运行时模式：E2B运行时（microVM）和containerd运行时（裸容器），分别适用于不同场景。

## 1.1 特性清单

| ofep编号 | 特性名称 | SIG组 | 特性描述 |
| -------- | -------- | ----- | -------- |
| 001 | FluxSandbox沙箱集群调度引擎 | sig-agent-sandbox | 声明式沙箱组管理、自动调度、生命周期管理（创建/运行/回收）、高性能调度 |
| 002 | FluxSandbox对接openEuler E2B沙箱运行时 | sig-agent-sandbox | E2B microVM运行时对接，支持沙箱创建/销毁、数据面网络访问 |
| 003 | 沙箱拓扑亲和调度 | sig-agent-sandbox | 多超节点场景下沙箱均匀分布、拓扑打分、动态启停降级 |
| 004 | 沙箱快照预热 | sig-agent-sandbox | 快照预热任务创建/查询、端到端预热、负载均衡、故障恢复 |
| 005 | 支持E2B运行时沙箱增量快照 | sig-agent-sandbox | Checkpoint端到端生命周期、快照持久化（对象存储GCS/S3）、沙箱恢复（Restore）、暂停/恢复、系统级集成 |

## 3.2   约束说明

1. containerd运行时不支持暂停/恢复/快照能力。
2. E2B运行时下`entrypoint`和`env`不注入microVM，沙箱内环境由模板决定。
3. 沙箱资源规格由SandboxGroup的`sandboxResources`统一决定，创建请求中的资源参数不生效。
4. 快照预热依赖PostgreSQL和MoonCake etcd，需提前配置。
5. 拓扑亲和调度需要多超节点（superpod）环境，节点需打`unifiedbus.com/superpod`标签。

### 4.2.2 性能测试执行统计数据

性能测试使用 MockRuntime（mock 0ms）模拟 Agent 数据面运行时，排除真实运行时的干扰，纯粹验证 flux-sandbox 调度链路的性能基线。测试集群为 9 节点 Kubernetes 集群，配置 6 个 SSG（总容量 30000），opensandbox-server 实例数 20。

| 测试项 | 测试项描述 | 用例执行结果 | 发现问题单数 |
| -------- | -------- | ------------ | ------------ |
| sandbox-IT-001 | 单请求调度时延：Agent 运行时为 MockRuntime（mock 0ms），5轮测试，端到端调度时延16ms~37ms，通过<50ms目标。其中 Scheduler allocate_ms 仅0.2ms~0.3ms，核心调度链路时延极短 | 通过 | 0 |
| sandbox-IT-002 | 3000并发创建吞吐：Agent 运行时为 MockRuntime（mock 0ms），预热30000沙箱资源池，10轮30000并发压测，QPS稳定在3300~4600，通过>=3000 QPS目标；3000并发完成耗时估算0.65s~0.79s，通过<1s目标 | 通过 | 0 |
