# 异构算力调度特性测试方案

# 1. 特性描述

*Volcano是Kubernetes的的批处理系统，它专门为高性能工作负载设计，如大数据和 AI 应用程序。Volcano 通过提供高级的作业调度功能，增强了 Kubernetes 在这些领域的能力。本特性提供了方便快捷的 Volcano 调度策略配置能力，以及 NUMA 级的调度能力*

## 2.2 功能测试方案

- *SR-1  NUMA节点亲和性*
  
  | 场景描述                                         | 测试方案设计                                                                                 | 预期结果                                                                          | 备注  |
  |----------------------------------------------|----------------------------------------------------------------------------------------|-------------------------------------------------------------------------------| --- |
  | 配置single-numa-node的pod亲和到single-numa-node节点上 | 节点的策略分别为single-numa-node、best-effort、restricted、none时，配置single-numa-node的pod亲和         | 仅允许调度至单NUMA节点，其他情况均为不可调度                                                      |     |
  | 配置restricted的pod亲和到restriceted节点上            | 节点的策略分别为single-numa-node、best-effort、restricted、none时，配置restricted的pod亲和               | 单NUMA节点的CPU容量上限大于等于申请值时，仅允许调度到单NUMA节点。<br/>单NUMA节点的CPU容量小于申请值时，可允许调度至多个NUMA节点 |
  | 配置beste-effort的pod亲和到best-effort节点上          | 节点的策略分别为single-numa-node、best-effort、restricted、none时，配置best-effort的pod亲和              | 优先调度至单NUMA节点，如果单NUMA节点无法满足CPU申请值，允许调度至多个NUMA节点                                |
  | 资源numa亲和                                     | 实现kubelet在分配负载资源时，确保分配的cpu和内存在同一个NUMA上                                                 |                                                                               | |
  | numa亲和策略配置                                     | 通过在前台开启或关闭NUMA亲和策略，配置默认调度器策略分别为single-numa-node、best-effort、restricted、none时，测试内存的访问效率 | 开启NUMA亲和策略，可以提升内存的访问效率；关闭后，内存访问效率比开启时慢                                        | |

- *SR-2  扩展调度策略*
  
  | 场景描述             | 测试方案设计                                                                 | 预期结果                                                                          | 备注                 |
  |------------------|------------------------------------------------------------------------|-------------------------------------------------------------------------------|--------------------|
  | Binpack调度策略      | 安装Volcano NUMA Scheduler拓展组件后，默认使用策略。通过前台界面配置Binpack调度策略权重以及 CPU、内存的权重 | Binpack 策略默认生效                                                                |                    |
  | 优先级调度与抢占策略       | 在集群资源不足、充足时，在前台开启优先级调度与抢占策略，配置高优先级、低优先级，查看业务的运行情况                      | 集群资源充足时，业务高优先级和低优先级都正常运行；集群资源不足时，低优先级业务会首先遭到驱逐，优先保障高优先级业务                     |                    |
  | 公平调度策略         | 在前台开启或关闭 公平调度，查看集群业务的吞吐量是否增强                                           | 当Job具有多个资源时，将Share值最大的资源作为主资源，在进行优先级调度时，仅根据主资源的Share值进行优先级调度                  | Share值：最大最小化公平分配（max-min fairness share） |
  | 组调度策略          | 在前台开启或关闭 组调度，分别配置Job下的pod已调度数量满足和不满足运行的数量minMember                     | 观察Job下的pod已调度数量是否满足运行的最小数量minMember，当Job的 最小运行数量得到满足时，为Job下的所有pod执行调度动作，否则不执行 |                    |
  | 按照默认设置修改调度策略及调度器 | 用户配置好默认调度策略后，后台对用创建的请求进行拦截，修改其默认调度器和默认调度策略      | 默认调度器和默认调度策略修改成功                                                              |                    |
