[URL测试-目录](https://gitee.com/openfuyao/docs/tree/master/docs/docs/4_%E5%AE%89%E8%A3%85%E6%8C%87%E5%AF%BC)

# 1. 特性描述

openFuyao容器平台需要面向用户提供应用的生命周期管理能力，允许用户直接创建应用或通过应用市场选择应用进行创建。

## 1.1 特性清单

| IR编号 | 特性名称                                   | 特性描述                                                     | 开发团队 | 备注                                                         |
| ------ | ------------------------------------------ | ------------------------------------------------------------ | -------- | ------------------------------------------------------------ |
| IR-12  | 平台基础能力 —— 提供应用的生命周期管理能力 | 平台支持应用的全生命周期管理，包含应用的创建/启动/停止/删除/升级，提供应用的状态监控和查询 | 应用组   | IR-12包含应用创建和应用运维2个特性，本方案仅覆盖应用创建特性（应用运维测试方案有独立文档） |

## 1.2 SR分解清单

| SR编号    | 需求描述                     | 关联功能                 | 备注 |
| --------- | ---------------------------- | ------------------------ | ---- |
| SR-12-1-1 | 新增通过yaml方式创建应用功能 | 提供应用的创建能力       |      |

# 2. 特性分层测试方案

## 2.1 总体方案

- 测试目标：验证平台提供的应用创建/查看能力，用户可以通过yaml、helm创建应用。

- 时间进度：

  | 开始日期 | 结束日期 | 工作日 | 阶段                                           | 备注 |
  | -------- | -------- | ------ | ---------------------------------------------- | ---- |
  | 4.1      | 5.10     |        | 特性开发+前后台联调                            |      |
  | 5.11     | 5.14     |        | 测试执行（功能、安全、自动化测试等）+issue提交 |      |
  | 5.15     | 5.25     |        | bug修复+回归验证                               |      |

- 风险评估：从开始转测到测试结束的时间跨度较短（5.11-5.25，11个工作日），需要执行各项测试、提交/跟踪issue、bug修复、回归验证等。所以需要测试团队在4月份进行充分准备（深入熟悉需求、细致的设计测试用例），防止测试时间不足导致测试不充分。

- 重点/难点：NA

- 待定事项：NA

- 入口标准：
  1. 特性满足质量标准，达成需求设计要求目标
  
- 出口标准：
  1. 方案规划的测试活动涉及测试用例100%执行完毕
  2. 无block问题遗留，其它遗留问题要有相应规避措施或说明
