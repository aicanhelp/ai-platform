# 平台可插拔特性测试方案



# 1. 特性描述

为了支持日渐丰富的云原生使用场景，openFuyao引入扩展组件概念，希望通过可插拔的架构设计，为用户提供更高效、灵活、定制化的云原生使用体验。openFuyao可插拔架构的前端设计从前端页面、后台K8s资源、扩展组件管理服务三个层面，将平台前台功能解耦为Console与扩展模块页面。不仅允许用户依据自身需求，进行扩展组件的热插拔管理，包括安装、卸载、启用、停用等操作，还提供一系列配置能力，支持用户自主开发第三方扩展组件。

# 2. 特性分层测试方案

## 2.1 总体方案

- 测试目标：从console页面、console service、扩展组件管理三个层面，验证前端可插拔架构的实现，包括平台基础功能与扩展功能解耦，允许平台管理人员根据需要动态管理扩展组件的装卸、启停，支持用户按需进行三方扩展组件开发，根据用户的权限动态加载与扩展组件相关的前端组件等。

- 时间进度：

  | 开始日期 | 结束日期 | 工作日 | 阶段                                           | 备注 |
  | -------- | -------- | ------ | ---------------------------------------------- | ---- |
  | 4.1      | 5.10     |        | 特性开发+前后台联调                            |      |
  | 5.11     | 5.21     |        | 测试执行（功能、安全、自动化测试等）+issue提交 |      |
  | 5.22     | 5.25     |        | bug修复+回归验证                               |      |

- 风险评估：从开始转测到测试结束的时间跨度较短（5.11-5.25，11个工作日），需要执行各项测试、提交/跟踪issue、bug修复、回归验证等。所以需要测试团队在4月份进行充分准备（深入熟悉需求、细致的设计测试用例），防止测试时间不足导致测试不充分。

- 重点/难点：本特性除了页面布局、接口可以直接测试，其余Console server等测试起来不是很直观，可能需要从端到端角度来验证。

- 待定事项：NA

- 入口标准：

  1. 特性满足质量标准，达成需求设计要求目标

- 出口标准：
  1. 方案规划的测试活动涉及测试用例100%执行完毕
  2. 无block问题遗留，其它遗留问题要有相应规避措施或说明

## 2.3 自动化测试方案

接口文档：https://gitee.com/openfuyao/enhancements/blob/master/design/architecture/%E5%89%8D%E7%AB%AF%E5%8F%AF%E6%8F%92%E6%8B%94%E6%9E%B6%E6%9E%84%E7%89%B9%E6%80%A7%E8%AF%B4%E6%98%8E%E4%B9%A6/%E5%89%8D%E7%AB%AF%E5%8F%AF%E6%8F%92%E6%8B%94%E6%9E%B6%E6%9E%84%E7%89%B9%E6%80%A7%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3.md

当前设计文档中共规划6个接口，包括自定义资源类型ConsolePlugin的POST增、DELETE删、GET查、PUT替换/创建、PATCH更新等。

接口依赖：PATCH更新、DELETE删除至少需要1个已存在的ConsolePlugin资源；其余按照接口文档设计自动化用例，分别执行即可。

当前设计文档中共规划6个接口，包括：

- ConsolePlugin相关接口：

1. 列出全部存在的ConsolePlugin资源
2. 创建一个ConsolePlugin资源
3. 获取特定ConsolePlugin资源
4. 替换特定ConsolePlugin资源，若不存在则创建
5. 更新特定ConsolePlugin资源
6. 删除特定ConsolePlugin资源
