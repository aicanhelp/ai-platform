# 日志特性测试方案

# 1. 特性描述

对日志模块能力进行增强，包括日志收集、管理、定位、采集、告警、下载能力

## 1.1 特性清单

| IR编号 | 特性名称                   | 特性描述                                                                                      | 开发团队 | 备注  |
| ---- | ---------------------- | ----------------------------------------------------------------------------------------- | ---- | --- |
| IR-6 | 提供平台基础能力-日志扩展组件的前、后台开发 | 日志组件作为可扩展组件单独提供，当用户安装日志模块组件后，前台增加日志页面，该页面在admin用户登录后能提供日志查看、按条件筛选功能。提供告警上报机制给中心告警模块上报告警信息 | 平台组  |     |

## 1.2 SR分解清单

| SR编号     | 需求描述               | 关联功能        | 备注  |
| -------- | ------------------ | ----------- | --- |
| SR-6-1-1 | 提供预置日志采集源          | 提供日志采集源管理能力 |     |
| SR-6-1-2 | 提供日志采集源的查看能力       | 提供日志采集源管理能力 |     |
| SR-6-2-1 | 提供按各种筛选条件进行日志查询的能力 | 提供日志查询能力    |     |

## 2.3 自动化测试方案

自动化测试框架选型：python+pytest+allure+jenkins

使用python编程语言，结合目前使用最广泛的框架pytest，最后集成allure插件生成有界面的测试报告，通过jenkins任务定时运行。

接口文档：https://gitee.com/openfuyao/enhancements/blob/master/design/feature/%E6%97%A5%E5%BF%97%E7%89%B9%E6%80%A7%E8%AE%BE%E8%AE%A1%E8%AF%B4%E6%98%8E%E4%B9%A6/%E6%97%A5%E5%BF%97%E5%90%8E%E7%AB%AF%E6%8E%A5%E5%8F%A3%E6%96%87%E6%A1%A3.md

测试设计思路：

日志模块属于扩展组件，在安装后需要确保查询和筛选日志、获取日志采集源、预置告警规则接口正常，通过接口自动化测试能更方便快速检测系统接口是否正常运行。涉及8个get接口，在设计过程中，详细理解接口文档给出的接口定义、请求参数、响应格式、各错误状态码等信息，保证在写用例的过程中，尽量全面覆盖各种情况。
