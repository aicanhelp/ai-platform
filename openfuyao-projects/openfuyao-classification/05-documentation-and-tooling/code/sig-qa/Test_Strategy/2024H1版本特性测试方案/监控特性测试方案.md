# 监控特性测试方案

# 1. 特性描述

在先前版本基础的监控能力进行功能增强，包括提供默认的监控大屏供容器平台管理员查看，提供预置的监控告警规则，提供预置的监控对象以及对监控对象的管理

## 1.1 特性清单

| IR编号 | 特性名称                 | 特性描述                                                            | 开发团队 | 备注  |
| ---- | -------------------- | --------------------------------------------------------------- | ---- | --- |
| IR-5 | 提供平台基础能力-监控组件的前、后台开发 | 前台增加监控大屏，admin用户登录后能对平台所有资源的监控对象和监控信息进行查看。提供告警上报机制给中心告警模块上报告警信息 | 平台组  |     |

## 1.2 SR分解清单

| SR编号     | 需求描述                | 关联功能        | 备注  |
| -------- | ------------------- | ----------- | --- |
| SR-5-1-1 | 提供预置的监控对象           | 提供监控对象的管理功能 |     |
| SR-5-1-2 | 提供对监控对象的增、删、改、查操作能力 | 提供监控对象的管理功能 |     |
| SR-5-2-1 | 增加一个初始的默认监控大屏       | 提供默认监控大屏    |     |

## 2.3 自动化测试方案

自动化测试框架选型：python+pytest+allure+jenkins

使用python编程语言，结合目前使用最广泛的框架pytest，最后集成allure插件生成有界面的测试报告，通过jenkins任务定时运行。

接口文档：https://gitee.com/openfuyao/enhancements/blob/master/design/feature/%E7%9B%91%E6%8E%A7%E7%B3%BB%E7%BB%9F%E7%89%B9%E6%80%A7%E8%AF%B4%E6%98%8E%E4%B9%A6/%E7%9B%91%E6%8E%A7%E7%B3%BB%E7%BB%9F%E5%90%8E%E7%AB%AF%E6%8E%A5%E5%8F%A3%E6%96%87%E6%A1%A3.md

测试设计思路：

监控模块作为核心组件，本版监控功能有指标采集及查询、预置监控目标、预置基本规则，因此需要保证监控组件接口无误，通过接口自动化测试能更方便快速检测系统接口是否正常运行。在设计过程中，详细理解接口文档给出的接口定义、请求参数、响应格式、各错误状态码等信息，保证在写用例的过程中，尽量全面覆盖各种情况。
