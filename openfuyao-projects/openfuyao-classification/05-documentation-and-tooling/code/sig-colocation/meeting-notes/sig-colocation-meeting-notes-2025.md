## 2025/5/7

- 与会人：

  王琦、张建津、李哲伟、郭宇翔、赵仁明、王清珺、李航宇、刘俊麟、胡洪驰、周永正

- 会议内容：

  对在离线混部630需求进行详细拆解说明，双方圈定开发范围并依据《在离线混部业务需求拆解.xlsx》对一阶段目标达成一致。

- 会议结论：

  1. 同意定义的三级QoS-level，将在线业务拆解成HLS和LS，HLS对应独占cpu和的guranteed pod，不可超卖资源，LS的pod可超卖资源。

  2. 基于volcano的负载均衡调度当前版本使用volcano默认项，而基于在线/离线资源实际使用量的负载均衡调度需要后续版本详细考量后再做。

  3. ColocationMatchRule（类似koordinator 的colocationProfile）是快速添加混部负载的易用性功能，630版本负责功能整体打穿，该功能放到后续版本规划来做。

  4. 同意在计算超卖资源时刨除HLS类别pod的资源使用量，具体修改需开发人员结合公式确定；同意超卖agent（完全我们开发可控的agent）使用在代码中检查节点是否存在标签而非通过部署时加入亲和性的方式适配在混部节点上功能才生效的需求。

- 遗留问题：

  1. 联通云确认开发联调环境是否可用。

  2. 联通云评估下混部基础监控部分的工作量，下次例会进行划分。

  3. 经讨论后，联通云负责的超卖部分需修改的两处需要同步给责任人。

## 2025/3/10

- 与会人 <br/>

  张建津、郭宇翔、杨洋、李哲伟、吴景、李晓峰、刘晓双、潘捷、陈伦、李航宇、周永正、朱雪仪 <br/>

- 会议议程

  华为侧分享openFuyao2503版本在离线混部和超卖集成的进展，提出3个当前架构下融合的问题，并对25年openFuyao在离线混部的整体规划进行分享。

- 会议结论

  openFuyao在离线混部大方向的设计双方达成一致，认可以下大颗粒度需求并会在下次例会进行详细讨论：
  
    1. 开发统一的调度插件
    2. 开发统一的重调度插件
    3. 对在离线混部特性的调度进行统一的调度配置管理
    4. 超卖工作负载具备将外层超卖标签同步给其控制的pod的能力（对齐混部准入逻辑）

  讨论中提出如下想法，可供后续细化参考：
    1. 调度插件是否要考虑使用volcano，volcano实现了一些AI调度需要的插件（gang-scheduler，拓扑感知scheduler）
    2. 后续rubik的agent是否和现有的agent合一成为一个manager-agent
