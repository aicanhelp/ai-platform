## 摘要

openFuyao 社区已经具备漏洞感知、修复、披露能力。为提升下游自动化消费CVE信息的能力，本提案新增： **CVE JSON FEED** 能力：通过 OBS 静态托管对外提供标准化漏洞记录（CVE JSON v5.1 record），并提供一个稳定入口的分发索引（index.json），下游可周期性拉取并解析，无需社区提供 API 服务。


本提案范围内仅提供：
- 文件分发：`index.json` + `all.ndjson.gz`（全量）
- 记录格式：CVE JSON v5.1（以单条 record 为最小标准单位）
- 校验：sha256（可选增强：签名）

## 动机

### 目标

- 对外提供可机器消费的 CVE 数据源，支持下游安全平台、SBOM/依赖审计工具、制品安全系统离线同步。
- 采用文件分发，不引入 API 运行成本。
- 记录内容尽可能遵循 **CVE JSON v5.1**，降低下游适配成本。
- index.json 提供稳定入口，支持下游做内容变更判断（基于 sha256/ETag），避免仅靠时间戳误判。

### 非目标

- 不实现在线查询 API。
- 不承诺提供增量 feed（modified/recent）能力（后续可扩展）。
- 不在本提案中用CNA 或自动分配 CVE ID；若某些记录没有 CVE ID，可在后续提案扩展为 Advisory 格式（不在本提案范围）。
- 不对外公开敏感的内部细节（如未公开的漏洞信息、内部工单链接、未脱敏的日志）。

## 提案

对外发布一个“全量 feed”目录，包含：
- `index.json`：分发索引（自定义协议，稳定入口）
- `all.ndjson.gz`：全量数据（NDJSON，每行一条 CVE JSON v5.1 record，gzip 压缩）
- `cve-list.json`：轻量速查，提供CVE的基本信息，数据量极小。

### 用户故事（可选）

- 故事 1：企业下游安全平台每天拉取 openFuyao `index.json`，若全量 hash 未变化则不下载大文件；若变化则下载全量并入库。
- 故事 2：用户希望快速查看“最近更新的 CVE 列表”，无需解析大文件，通过 `cve-list.json` 完成展示与告警决策（可选能力）。

### 注释/约束/警告（可选）

- `index.json.generatedAt` 仅表示“发布件生成时间”，不能作为“内容变更”唯一依据；内容是否变更以 `sha256` 判断。
- 记录内容必须符合披露边界：仅发布已公开（PUBLISHED）的漏洞记录。

### 风险与缓解措施

- 风险：下游仅比较 `generatedAt` 导致误判与重复下载。
  - 缓解：index.json 强制包含 `sha256`（或要求 OBS/CDN 提供稳定 ETag），并在协议中明确“以 hash 判断内容变化”。
- 风险：数据被篡改或污染。
  - 缓解：提供 `sha256`，可选提供签名；下游校验后再入库。
  本提案不涉及API、无敏感信息，经过比对，不涉及《openFuyao安全设计规范》中的任何风险。

## 设计细节

### 总体结构（OBS 文件发布）

建议固定目录（示例）：

- `/<feedVersion>/index.json`
- `/<feedVersion>/all.ndjson.gz`
- `/<feedVersion>/cve-list.json`（可选）

其中 `<feedVersion>` 为分发协议版本（如 `v1`），与 CVE JSON 版本（5.1）区分。

### 数据源与映射（内部漏洞 → CVE JSON v5.1）

内部需要一个“发布视图”模型（概念，就是从内部数据映射CVE JSON用）：
- 输入：将现有的漏洞库（DB或者文本）的数据结构（CVE ID、公告、修复链接、受影响组件等）
- 输出：一条 CVE JSON v5.1 record（或多语言描述）

映射原则：
- 对外输出只包含已公开信息
- 受影响范围尽可能精确（版本区间、fixed in）

### Feed 文件定义

#### 1) index.json（分发索引）

**用途**
- 下游稳定入口：知道去哪里下载全量
- 下游判断是否需要重新下载：对比 `sha256` 
- 下游获知全量覆盖的更新时间范围：`maxUpdated`

**文件名**
- `/<feedVersion>/index.json`

**字段定义（建议 v1 固化如下）**

| 字段路径 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `feedVersion` | string | 是 | 分发协议版本，如 `"v1"` |
| `recordFormat` | string | 是 | 固定 `"CVE_JSON_5.1"` |
| `generatedAt` | string(datetime, RFC3339) | 是 | 本次生成 index 的时间 |
| `full.path` | string | 是 | 全量文件相对路径，如 `"v1/all.ndjson.gz"` |
| `full.contentEncoding` | string | 是 | 固定 `"gzip"` |
| `full.sha256` | string(hex) | 是 | 全量文件内容 sha256（对压缩文件本体计算） |
| `full.recordCount` | integer | 是 | 全量包含的 record 数量 |
| `full.minUpdated` | string(datetime) | 否 | 全量中最早的 `cveMetadata.dateUpdated` |
| `full.maxUpdated` | string(datetime) | 是 | 全量中最新的 `cveMetadata.dateUpdated` |
| `optional.cveListPath` | string | 否 | 速查表路径，如 `"v1/cve-list.json"` |
| `optional.cveListSha256` | string(hex) | 否 | 速查表 sha256 |

**示例**

```json
{
  "feedVersion": "v1",
  "recordFormat": "CVE_JSON_5.1",
  "generatedAt": "2026-07-16T08:15:00Z",
  "full": {
    "path": "v1/all.ndjson.gz",
    "contentEncoding": "gzip",
    "sha256": "3b5d5c3712955042212316173ccf37be8000000000000000000000000000000",
    "recordCount": 2,
    "minUpdated": "2026-07-12T03:00:00Z",
    "maxUpdated": "2026-07-16T08:10:00Z"
  },
  "optional": {
    "cveListPath": "v1/cve-list.json",
    "cveListSha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
  }
}
```

#### 2) all.ndjson.gz（全量正文）

**用途**
- 承载全量漏洞记录（核心数据）
- 下游无需 API：下载后本地解析、入库、索引、检索

**文件名**
- `/<feedVersion>/all.ndjson.gz`

**格式**
- gzip 压缩
- 解压后为 NDJSON：一行一个 JSON object
- 每行 object 是一条 **CVE JSON v5.1 record**

**每行 record 的字段要求（CVE JSON v5.1 子集约束）**

下表为“openFuyao 发布至少应填”的字段约束（不是 v5.1 全量 schema 的复述）：

| 字段路径 | 必填 | 含义/要求 |
|---|---|---|
| `dataType` | 是 | 固定 `"CVE_RECORD"` |
| `dataVersion` | 是 | 固定 `"5.1"` |
| `cveMetadata.cveId` | 是 | 如 `"CVE-2026-0001"` |
| `cveMetadata.state` | 是 | 建议仅发布 `"PUBLISHED"`；撤回可扩展（后续） |
| `cveMetadata.datePublished` | 是 | 首次公开时间 |
| `cveMetadata.dateUpdated` | 是 | 记录最后变更时间 |
| `cveMetadata.assignerShortName` | 是 | `"openfuyao"`（或你们统一短名） |
| `containers.cna.descriptions[]` | 是 | 至少 1 条；`lang` 建议提供 `zh` 或 `en` |
| `containers.cna.affected[]` | 是 | 至少 1 条受影响对象与版本范围 |
| `containers.cna.references[]` | 是 | 至少包含你们公告链接（稳定 URL） |
| `containers.cna.metrics[]` | 否 | 推荐包含 CVSS v3.1/v4.0（如已具备） |
| `containers.cna.problemTypes[]` | 否 | 推荐 CWE（如可得） |


**NDJSON 示例（两条 record，两行）**

```json
{"dataType":"CVE_RECORD","dataVersion":"5.1","cveMetadata":{"cveId":"CVE-2026-0001","state":"PUBLISHED","datePublished":"2026-07-10T02:00:00Z","dateUpdated":"2026-07-16T08:10:00Z","assignerShortName":"openfuyao"},"containers":{"cna":{"descriptions":[{"lang":"zh","value":"openFuyao RBAC 中存在..."}],"affected":[{"vendor":"openfuyao","product":"rbac","versions":[{"status":"affected","version":">=1.2.0, <1.2.5"},{"status":"unaffected","version":">=1.2.5"}]}],"references":[{"url":"https://openfuyao.org/security/advisories/OFA-2026-0001"}],"metrics":[{"cvssV3_1":{"vectorString":"CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H","baseScore":9.8,"baseSeverity":"CRITICAL"}}]}}}
{"dataType":"CVE_RECORD","dataVersion":"5.1","cveMetadata":{"cveId":"CVE-2026-0002","state":"PUBLISHED","datePublished":"2026-07-12T03:00:00Z","dateUpdated":"2026-07-12T03:00:00Z","assignerShortName":"openfuyao"},"containers":{"cna":{"descriptions":[{"lang":"zh","value":"某三方依赖在特定场景下..."}],"affected":[{"vendor":"openfuyao","product":"rbac","versions":[{"status":"affected","version":">=1.1.0, <1.1.3"},{"status":"unaffected","version":">=1.1.3"}]}],"references":[{"url":"https://openfuyao.org/security/advisories/OFA-2026-0002"}]}}}
```

#### 3) cve-list.json（可选速查表）

**用途**
- 下游快速获取“有哪些 CVE、各自更新时间/严重性/公告链接”，无需下载与解析全量 NDJSON
- 支持做轻量告警决策：只关心高危/只关心某产品时，可先看列表

**文件名**
- `/<feedVersion>/cve-list.json`

**字段定义（建议）**

| 字段路径 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `generatedAt` | string(datetime) | 是 | 列表生成时间（快照时间） |
| `items[]` | array | 是 | 条目列表 |
| `items[].cveId` | string | 是 | CVE ID |
| `items[].dateUpdated` | string(datetime) | 是 | 同 record 的 `cveMetadata.dateUpdated` |
| `items[].baseScore` | number | 否 | baseScore |

**示例**

```json
{
  "generatedAt": "2026-07-16T08:15:00Z",
  "total": 2,
  "items": [
    {
      "cveId": "CVE-2026-0001",
      "dateUpdated": "2026-07-16T08:10:00Z",
       "baseScore": 9.8 
    },
    {
      "cveId": "CVE-2026-0002",
      "dateUpdated": "2026-07-12T03:00:00Z",
      "baseScore": 7
    }
  ]
}
```

### 时间戳与一致性约束

为避免下游困惑，建议在协议中固定以下约束：

- `max(items[].dateUpdated) == index.full.maxUpdated`（若启用 cve-list）
- `items[].dateUpdated <= cve-list.generatedAt`
- `index.generatedAt >= cve-list.generatedAt`（同一流水线建议取相等值）
- 下游判断“内容是否变化”以 `index.full.sha256`（或 HTTP ETag）为准，而非仅比较 `generatedAt`

### 校验、签名与安全

- `sha256`：index.json 强制提供 `all.ndjson.gz` 的 sha256
- 传输安全：OBS 对外通过 HTTPS；配合 CDN 可提升可用性
- 可选签名（后续增强，不影响 v1 交付）：对 `index.json` 或 `all.ndjson.gz` 做签名并发布签名文件（如 `.sig`），下游校验后再入库

### 生成与发布流程

- 触发：
  - 漏洞披露发布（PUBLISHED）时触发一次生成
  
    
  
- 步骤：
  - 从披露系统导出已公开漏洞集
  - 映射为 CVE JSON v5.1 record
  - 校验：schema + 必填字段 + 时间一致性 + URL 合法性
  - 输出 `all.ndjson` → gzip 得到 `all.ndjson.gz`
  - 计算 sha256，生成 `index.json`
  - 生成 `cve-list.json`
  - 上传 OBS，并确保写入顺序：先上传大文件与 list，再上传 index（避免 index 指向不存在对象）

### 兼容性与演进策略

- `feedVersion` 用于版本演进（v1→v2）
- `recordFormat` 固定标识 record 标准（CVE JSON v5.1）
- v1 只做全量；后续如引入增量文件，可在 index.json 新增 `deltas[]`，不破坏现有 `full` 字段

### 测试计划

##### 先决条件测试更新
- 明确披露数据源字段到 record 字段的映射表（内部）
- 明确“哪些漏洞可对外发布”的规则（仅 PUBLISHED）

##### 单元测试
- 时间戳关系校验（maxUpdated、generatedAt 约束）
- sha256 计算与一致性

##### 集成测试
- 功能较小，直接做E2E测试

##### e2e 测试
- 下游模拟：拉取 index → 对比 sha256 → 下载全量 → 解析两条 record 成功

### 毕业标准

- 对外可用的 `index.json + all.ndjson.gz`，且全量 record 符合 v5.1 基础字段要求；下游可以稳定同步。

## 生产准备情况评审问卷

### 功能启用和回滚

- 启用：在 OBS 上公开 `v1/` 目录对象即可
- 回滚：恢复上一版 `index.json` 或切换到上一版目录



### 依赖项

- 依赖 OBS（对象存储）对外 HTTPS 访问

### 可扩展性

- 后续可扩展：
  - 增量包（modified）
  - 签名文件
  - 额外格式（如 OSV）并行输出（新提案）

### 故障排除

- 下游报解析失败：
  - 先核对 `recordFormat` 与 record 是否为合法 JSON
  - 校验 `sha256` 是否匹配
  - 抽样验证一条 record 是否符合 v5.1 必填结构

- 2026-07-16：形成方案初稿（provisional）。

## 缺点

- 仅全量方式在漏洞数量增长后可能导致下游下载成本上升（可通过后续增量包缓解）。
