### 2、发布流程与工具链优化

- 完成：需求开发、问题修复、漏洞管理等基本能力，基本完成版本发布流水线；
- 完成：《版本号和tag定义规则》《特性发布成熟度管理规范》《社区发行版生命周期与内核切换策略》《社区开发流程说明》《需求申请流程》等规范制定；
- 发布能力：支持按特性发布能力构建；

### 3、跨SIG与社区协同

- 社区内协同：
  - 建立与TC、QA SIG、Doc SIG、Infra SIG、安全SIG、各技术SIG的常态化协同机制，每二周召开社区版本例会，同步版本进度、协调解决特性集成、兼容性测试中的问题，确保各SIG组的开发工作与版本发布计划同频推进；
  - RM SIG也参与到各技术SIG组的特性设计的评审，确保特性交付和竞争力规划保持一致；
  - 例行在TC和筹备委员会汇报版本交付进展。
- 外部协同：
  - 配合社区与其他开源社区（如openEuler等）开展版本协同适配工作，如灵衢设备适配、NUMA亲和、众核调度等特性
  - 多个特性推动upstream上游（如volcano、Mooncake、Ray等）。

### 4、版本质量与安全保障

- 推进测试前移，即开发者测试，以及自动化测试比例提升；
- 联合QA SIG，推进社区联合验证；
- 梳理开源三方件使用，并合规声明；
- 增强合规工具扫脚和测试，实现0片段引用、License/CopyRight合规风险清零；
- 把安全、合规、可信理念和测试结论引入版本外发评估checklist；

## 2026年 重点建设方向

- 流程与规范：原则上进一步优化开发流程，追求轻量化和高效
  - 协同技术SIG组、安全SIG、Infra SIG、QA SIG，持续对标先进社区（k8s、openEuler），减少手工维护，工具化完成社区版本定义、制作、验证与发布；
  - 协同技术SIG组，完善组件管理，构建SIG组自主管理组件能力；
  - 完善规范：《补丁管理规范》、推动内核SIG组完善K8s切换流程等
  - 协同SIG组推进社区软件工程能力和安全能力的提升；
- 质量与安全：
  - 持续推进开发者测试和自动化测试
  - 完善安全出口的管理，增加安全测试和安全评估；
  - 配合安全SIG组，建立漏洞修复机制；
- SIG组运营：
  - 建立完善SIG组人员更新与升级制度，提升社区成员参与度，例会组织轮值；
  - 加强社区版本和伙伴自用版、商业发行版间协同，竞争力特性快速同步上市；
  - 参加社区运营meetup活动，提升SIG影响力；
