# release-management/RM Sig

本SIG组主要工作职责是在社区协调各开发SIG的Maintainer、QA等各个团队，完成openFuyao社区版本的发布工作。主要职责如下：

**Maintainer职责包括待不限于以下几点：**

- 规划openFuyao版本的发行时间表。
- 在开发/测试周期中跟踪（更新补丁或功能feature）的开发状态。
- 发布协调（在QA，发布工程师，技术委员会等范围内），参与相关组和发布相关等会议。
- 负责openFuyao项目的交付过程协调。
- 版本评审发布决策。

**Committer职责包括待不限于以下几点：**

- 同步版本规划/计划。
- 提名/推荐新特性。
- 跟踪特性交付进度。
- 评审新特性。
- 评审版本质量。
- 撰写或更新版本相关文档。
- 优化版本管理流程。
- 组织线下版本相关活动。

## maintainer竞选流程及原则

由maintainer和扩展成员提名（个人先向以上成员提出申请），RM sig评审

- committer成员连续6个月以上对社区有持续贡献，且至少有一个特性为版本关键特性（存在于release notes）。
- committer成员持续参加RM sig例会，近6个月与会率70%以上。
- committer成员代表伙伴团队可独立参与社区决策。
- 对release管理/社区版本运作有突出贡献者个人和组织自我推荐（贡献自我举证）。

## maintainer变更流程及原则

- 主动退出或者release提议退出，RM sig评审后发起更新。
- 主动退出或者连续6次以上无故不参与RM sig例会。
- 个人或者所属团队，连续6个月无社区贡献。

## committer变更流程及原则

- 主动退出或者release提议退出，RM sig评审后发起更新。
- 主动退出或者连续6次以上无故不参与RM sig例会。
- 个人或者所属团队，连续6个月无社区贡献。

## committer新增流程及原则

- 各个伙伴团队主动提名，日常参与RM sig组例会，参与版本规划、计划、评审、决策等流程。
- 对本sig/社区版本运作有突出贡献者个人和组织自我推荐（贡献内容自我举证，贡献形式不限）。
