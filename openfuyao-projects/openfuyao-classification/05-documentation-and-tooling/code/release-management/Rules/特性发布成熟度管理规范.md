# openFuyao 特性发布成熟度管理规范

## 1. 成熟度等级定义

openFuyao特性发布成熟度分为两个等级：

| 等级 | 描述 |
|------|------|
| 孵化期 | 功能已实现但稳定性、性能或用户体验有待进一步验证的特性 |
| 成熟期 | 已经过充分验证、稳定可靠、可大规模生产使用的特性 |

## 2. 特性成熟度衡量标准

| 评估维度 | 孵化期 | 成熟期 |
|---------|--------|--------|
| 技术架构 | 方案尚未冻结，仅具备基本可独立使用的能力，后续还要继续完善 | 方案经过多个版本验证，架构稳定可靠 |
| 接口 | 接口尚不稳定，后续版本可能存在非兼容性变更 | 接口稳定，后面版本接口保持持续兼容 |
| 升级 | 尚不提供升级，需要卸载后新安装 | 新版本提供升级 |
| 文档 | 仅使用指导 | 使用说明、开发者指南等全套文档 |
| 默认开启 | 默认不部署，需要专门部署和开启 | 允许默认开启 |
| 适用性&兼容性 | 仅提供部分场景和兼容性 | 支持多种稳定使用场景和兼容性要求 |
| 质量 | 功能测试用例通过率≥95%，无P0级别缺陷，P1级别缺陷≤3个 | 功能测试用例通过率100%，无P0/P1级别缺陷，P2级别缺陷≤2个 |
| 测试保障范围 | 聚焦功能覆盖 | 完整的测试覆盖，性能、稳定性、安全测试全部通过 |
| DT(行)覆盖率 | >=50% | >=80% |
| 自动化测试率 | 不强制要求 | >=80% |
| 是否已POC | 需要POC验证，核心功能可行 | 至少在一个社区版本中作为孵化期特性发布过，有实际用户使用案例 |

## 3. 操作环节

| 阶段 | 要求 | 说明 |
|------|------|--------|
| 特性需求登记阶段 | 在release_Plan文件中FeatureList中登记该特性在此版本的目标成熟度，QA SIG验收时参考此标准验收 |  |
| 社区版本出口评价阶段 | 社区版本测试报告中对该特性的评价，如有争议则以RM SIG结论为准，Release Notes中按照测试报告评价来标明 |  |
|  | 孵化期特性在特性包和组件版本号规划上，一般要求0.y.z规划，待成熟期后从1.y.z开始命名，其中依赖的已成熟期组件不受此限制 |  |
