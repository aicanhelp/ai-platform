# weight-dispatcher性能测试报告-v26.06

## 摘要

本报告在单存储节点、多计算节点场景下测试了 weight-dispatcher 从存储节点将模型权重分发到多个计算节点的性能。在 3 计算节点场景下，weight-dispatcher(TCP) 传输权重文件的 E2E 时间相较基线工具均有明显降低：

- 相较 rsync 降低 58.41%~65.94%；
- 相较 rclone 降低 72.45%~76.13%；
- 相较 netcat 降低 49.15%~52.72%；
- 相较基于存储节点物理网卡带宽上限推导的传统单源并发分发路径理论最短时间降低 39.02%~48.92%；相较传统树状分发路径理论最短时间降低 8.6%~23.38%。

测试结果满足性能加速 20% 以上的预期，且在本次测试范围内，目标节点数增加、模型权重规模增大时收益表现更明显。

### 结果分析

综合测试数据，在本次测试范围内可得出如下结论：

- 在各项权重分发场景下，weight-dispatcher 相较 rsync、rclone、netcat 等基线工具均降低了整体传输完成时间（E2E）；
- 从 2 个目标计算节点扩展到 3 个目标计算节点后，weight-dispatcher(TCP) 相较基线工具的 E2E 降幅整体扩大，说明在多目标分发场景下，减少源节点重复传输能够带来更明显收益；
- 随着模型权重规模增大，weight-dispatcher(TCP) 相较基线工具的 E2E 降幅整体更明显，说明在大模型权重分发场景下，传输优化收益更容易覆盖工具调度、建连、校验等额外开销；
- 在 3 计算节点场景下，weight-dispatcher(TCP) 相较基于物理带宽上限推导的传统单源并发分发路径理论最短时间降低 39.02%~48.92%，相较传统树状分发路径理论最短时间降低 8.6%~23.38%。该收益来自 weight-dispatcher 通过分片下载和计算节点间交换减少源节点重复出流量，而不是突破单链路物理带宽上限；
- 理论最短传输时间用于描述物理带宽约束下的参考下界，实际工具的 E2E 时间还会受到协议栈、文件数量、磁盘读写、并发调度和校验流程等因素影响；
- 当前项目代码对 RDMA 数据传输路径的适配仍不完善，传输过程中存在多次错误重传，导致本次测试中 weight-dispatcher 走 RDMA 路径的 E2E 时间高于 TCP 路径。后续将逐步完善 RDMA 路径的代码实现，降低重传带来的额外开销。

以上测试结果表明，在当前 TCP 路径下，weight-dispatcher 在本次权重分发测试场景中具备稳定的 E2E 性能收益，整体符合性能加速 20% 以上的预期。
