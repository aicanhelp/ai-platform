# AI推理新特性性能对比测试报告v26.03

## 1.概述

### 1.1. 测试目的

本文档针对v26.03AI推理集成部署（infernex）新增功能（智能路由路由容灾能力，AI推理弹性扩缩系统）进行性能基线对比测试，并对测试结果进行分析。

### 1.2. 版本目标

infernex在2603版本新增两个特性：智能路由容灾功能和AI推理弹性扩缩系统，因这两个功能均不涉及推理性能优化，故目标为验证开启上述新增功能推理性能无劣化。

### 1.3. 测试环境

#### 1.3.1. 硬件规格

|参数名|参数内容|
|---|---|
|产品名称|Atlas 800T A2 训练服务器|
|结构|4U机架式服务器|
|NPU|8 \* 昇腾910B4|
|CPU|4 \* 鲲鹏920|
|内存|32G \* 32|
|存储|2TB NVMe SSD|
|网络|8 \* 200GE QSFP接口直出，Roce协议|

#### 1.3.2. 软件规格
|软件|版本|
|---|---|
|操作系统|openEuler\-22.03\-LTS\-SP3|
|hermes-router|0.21.0|
|cache-indexer|0.21.1|
|vllm\-ascend|0.13.0|

## 2.测试内容

### 2.1.  测试组件范围

| AI推理组件类型 | 组件名称      | 规格选项                                                                                       |
| -------------- | ------------- | ---------------------------------------------------------------------------------------------- |
| 网关路由       | hermes-router | 路由策略:</br>- random</br> 容灾能力：</br>- on/off |
| AI推理弹性扩缩系统               |     pd-orchestrator          |                                                          是否开启：</br>- on/off                                     |

### 2.2. 路由策略

**random**：通过生成随机数选择后端进行请求转发。不考虑历史请求内容或缓存命中情况等要素，多个后端接收到的请求数量相对均衡。

### 2.2. 测试指标 

对于每一种测试场景，都会测试以下指标：

- 整体指标

| 指标名称                         | 指标含义        |
| -------------------------------- | --------------- |
| Benchmark Duration(ms)           | 整轮测试时间    |
| Total Requests                   | 总请求数        |
| Request Throughput(req/s)        | 每秒处理请求数  |
| Input Token Throughput(token/s)  | 每秒输入token数 |
| Output Token Throughput(token/s) | 每秒输出token数 |
| Total Token Throughput(token/s)  | 每秒总token数   |

- 每条请求P99指标

| 指标名称     | 指标含义                  |
| ------------ | ------------------------- |
| E2EL(ms)     | 端到端延迟                |
| TTFT(ms)     | 首token延迟               |
| TPOT(ms)     | 生成每个输出token所需时间 |
| ITL(ms)      | 相邻token输出时间间隔     |
| InputTokens  | 输入token数               |
| OutputTokens | 输出token数               |
| OutputTokenThroughput(token/s)  | 每秒输出token数          |


## 3. 性能测试设计与结果

针对infernex在2603版本新增两个特性：智能路由容灾功能和AI推理弹性扩缩系统，因这两个功能均与性能无关，故设计基线对比测试进行验证其开关是否影响基线性能。

- 场景1：仅开启智能路由容灾功能对比基线
- 场景2：仅开启AI推理弹性扩缩系统对比基线

注：基线为不开启任何优化功能，路由策略选择 random 策略，并且本测试报告中提到的实验所使用的推理后端模式为聚合模式。

### 3.1. 场景1：开启智能路由容灾功能对比基线

#### 数据集

| 数据集 | 备注 |
| ------ | ---- |
| ShareGPT_V3_unfiltered_cleaned_split  | 选取前1000簇多轮对话 |

ShareGPT_V3_unfiltered_cleaned_split 是一个在LLM社区中被广泛使用的、高质量的多轮对话数据集，它的核心特点是所有问题均来自真实用户场景，而非人工臆想或API轮询模拟，更贴近真实世界中的指令分布。

在推理过程中，所有请求的输出长度固定为 512 tokens。

在发送推理请求时，每条请求的构成为当前query所在对话簇中之前所有轮对话（query + answer）加本轮query构成，其中answer均为模型实际返回结果，固定为 512 tokens。

#### 实验参数

| 测试项 | gpu-memory-utilization | 实例数量 | TP  | 并发数 | 路由策略 |
| ------------ | ---------------------- | -------- | --- | ------ | -------- |
| 基线          | 0.8                    | 4        | 2   | 40     | random   |
| 仅开启智能路由容灾           | 0.8                    | 4        | 2   | 40     | random   |

#### 实验结果

| 测试项 | Benchmark Duration(ms) | Total Requests | Request Throughput(req/s) | Input Token Throughput(token/s) | Output Token Throughput(token/s) | Total Token Throughput(token/s) |
| ------ | ---------------------- | -------------- | ------------------------- | ------------------------------- | -------------------------------- | ------------------------------- |
| 基线   | 1036321.3932           | 3177           | 3.0628                    | 3255.7033                       | 1568.1313                        | 4823.8346                       |
|    仅开启智能路由容灾    |          1026341.9917              |    3177     |         3.0925             |         3360.2747     |   1583.3787            |        4943.6533          |

- 每条请求P99数据

| 测试项             | E2EL(ms) | TTFT(ms) | TPOT(ms) | ITL(ms) | InputTokens | OutputTokens | OutputTokenThroughput(token/s) |
| ------------------ | -------- | -------- | -------- | ------- | ----------- | ------------ | ------------------------------ |
| 基线               | 13702.6  | 396.1    | 26.5     | 111.0   | 5083.16     | 512          | 57.0833                        |
| 仅开启智能路由容灾 | 13225.6  | 384.8    | 25.5     | 102.5   | 5274.95     | 512          | 56.4264                        |

#### 结果分析

对比上表中的数据，可以看出在仅开启智能路由容灾功能的情况下，各项指标对比基线均没有产生大幅度的变动或下降，符合开启智能路由容灾能力对比基线性能无劣化的预期。
