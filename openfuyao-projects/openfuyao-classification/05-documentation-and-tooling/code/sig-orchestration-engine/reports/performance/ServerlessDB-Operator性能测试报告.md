# ServerlessDB Operator 性能测试报告

## 1. 概述

### 1.1 测试目的

验证 `serverlessdb-operator` 实例申请接口时延与资源池拉起能力：单实例、`200` 并发、`warm=1000` 规模申请时延，以及 `200→1000` 实例梯度拉起的成功率、耗时与资源占用。

### 1.2 验证目标

| 序号 | 用例编号 | 验证能力 | 验收目标 |
|:--:|---|---|---|
| 1 | `serverlessdb-IT-023` | 单实例申请接口时延 | HTTP `200`，时延 `< 1s` |
| 2 | `serverlessdb-IT-024` | `200` 并发申请接口时延 | `200` 个虚拟用户共 `200` 次请求，请求级时延 `< 1s`，失败数 `0` |
| 3 | `serverlessdb-IT-025` | `1000` 实例实拉起 + `warm=1000` 规模申请时延 | 拉起全部 `WarmReady`；`200` 个虚拟用户共 `1000` 次申请，请求级时延 `< 5s`、失败数 `0` |

### 1.3 测试环境

| 类别 | 配置 |
|---|---|
| IT-023/024 集群 | `192.168.201.34` 集群：3 master 高可用，`3×(8C/15.6Gi)`，K8s v1.34.3-of.1（arm64）；测试执行 2026-08-05 |
| IT-025集群 | `bke-cluster`：master-1/2/3 = `192.168.200.45/46/47`，`3×(32C/125.6Gi)`，K8s v1.34.3-of.1；测试执行 2026-09-23~24 |
| Operator | `serverlessdb-operator` |
| 实例 namespace | `serverlessdb` |
| 测试资源池 | `pool-perf`（IT-023/024，warm=200/200）、`pool-1000`（IT-025），测试后均已删除恢复现场 |
| 池模板 | `postgres:17`，requests `50m/128Mi`，limits `4C/4Gi`，`shared_buffers=32MB`（空闲内存降至 `~21.5Mi`/实例） |
| 申请参数 | `pg_version=17`，CPU `9m`，Memory `30Mi`；IT-05 中 `app_ref` 全局唯一 |
| 压测/采集工具 | `k6`（200 VU 模型）；kubelet `/stats/summary` 逐 Pod 采样，`2s` 间隔，覆盖全部节点 |

|---|---|---|---|
| 场景1 | 实例申请接口时延：单次、`200` 并发、`warm=1000` 规模 | IT-023 / IT-024 / IT-025 | `k6` |
| 场景2 | 资源池梯度拉起：`200→1000` 实例实拉起（`5` 轮） | IT-025 | 资源池 PATCH + 资源采样 |

### 2.2 测试指标

| 指标 | 口径 |

| 请求级时延 avg / P50 / P95 / P99 / Max | k6 `http_req_duration`（P99 经 `--summary-trend-stats` 输出），验收阈值 IT-023/024 `< 1s`、IT-025 `< 5s` |

## 3. 测试结果

### 3.1 实例申请接口时延（IT-023 / IT-024 / IT-025）

压测模型说明：k6 `-u VU -i 总请求数`，即 `VU` 个虚拟用户**共享**总请求数（非 VU×请求数）。IT-024 为 `200` 用户共 `200` 次（每用户 1 次）；IT-025 为 `200` 用户共 `1000` 次（每用户 5 次）。

| 用例 | 前置状态 | 总请求数 | avg | P50 | P95 | P99 | Max | 失败数 | 目标 | 判定 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|:--:|
| IT-023 单次申请 | warm=200 | 1 | `24.85ms` | - | - | - | - | `0` | `< 1s` | 通过 |
| IT-024 `200` 并发 | warm=200 | 200 | `532ms` | `579ms` | `711ms` | - | `776ms` | `0` | `< 1s` | 通过 |
| IT-025 `1000` 规模（5 轮） | warm=1000 | 1000/轮 | `1.40s` | `1.95~1.97s` | `2.00~2.01s` | `2.02~2.04s` | `2.04~2.08s` | `0` | `< 5s` | 通过 |

结果分析：

1. IT-023/024 全部通过：`200` 并发下 avg `532ms`、P95 `711ms`、Max `776ms`，满足 `< 1s` 目标；申请返回 `pod_id`、`pod_name`、`endpoint`。
2. IT-025 通过：`5` 轮重复验证全部 `100%` 成功、失败数 `0`，时延 P99 `2.02~2.04s`，满足 `< 5s` 目标。
3. **时延构成（IT-025）**：operator 侧处理时延 avg `1.39s`，与端到端 `1.40s` 基本重合（客户端+网络开销 `< 25ms`）；最小请求仅 `60~200ms`，P50 `1.95s` 为并发排队等待。即抬升来自 **`200` 并发在 operator 单副本入口的排队**（operator 租户客户端限流 QPS=100），而非池规模本身——同为 `200` 并发的 IT-024（warm=200）avg 仅 `532ms`，单发仅 `16ms`。

### 3.2 资源池拉起（IT-025）

每轮从池空（replicas=0）按 `200→500→1000` PATCH 拉起，`WarmReady` 后保持 `60s` 稳态，再以 k6 执行 `200` 用户共 `1000` 次申请，轮末全量复位。

> **口径说明**：`拉起耗时` 是池化预热成本（批量创建 Pod、一次性后台动作，无 `< 5s` 目标）；`< 5s` 验收目标仅针对**申请接口时延**——从已预热池中认领现成实例的接口响应速度（3.1 节）。二者不可比。

| 轮次 | 200 拉起 | 500 拉起 | 1000 拉起 | 拉起期 CPU 峰值 | 拉起期内存峰值 | 稳态 CPU 均值 | 稳态内存 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | `20s` | `29s` | `52s` | `16.6C` | `10.4Gi` | `5.13C` | `21.4Gi` |
| 2 | `19s` | `30s` | `52s` | `17.6C` | `12.0Gi` | `4.57C` | `21.3Gi` |
| 3 | `20s` | `30s` | `52s` | `16.8C` | `10.4Gi` | `4.87C` | `21.2Gi` |
| 4 | `19s` | `29s` | `56s` | `18.4C` | `11.3Gi` | `5.33C` | `21.1Gi` |
| 5 | `19s` | `30s` | `56s` | `18.4C` | `10.0Gi` | `4.20C` | `21.3Gi` |

资源值均为 3 节点合计（拉起期取 `PATCH→WarmReady` 窗口峰值，稳态取拉起完成后 `60s` 窗口均值，来自逐 Pod `2s` 间隔采样）。

结果分析：

1. **拉起快、全成功、可复现**：`5` 轮 × 3 梯度全部 `WarmReady`、无失败实例；`1000` 拉起耗时 `52~56s`（波动 `±2s`）。
2. **拉起期资源余量充足（含单节点维度）**：拉起期 3 节点合计 CPU 峰值 `16.6~18.4C`，**单节点**峰值 `5.3~8.3C`（占 `32C` 的 `17%~26%`）、内存峰值 `~6.5~6.9Gi`（占 `125.6Gi` 的 `~5%`），远离节点上限；内存随实例就绪爬坡，`READY` 后趋于稳态。
3. **稳态成本低**：稳态 CPU `4.2~5.3C`、内存 `21.1~21.4Gi`（≈`21.7Mi`/实例，CPU 每实例仅 `~4.6mC` 为毫秒级噪声），`1000` 实例稳态合计不足集群资源的 `1/5`。

## 4. 结论

| 验收项 | 目标 | 实测 | 判定 |
|---|---|---|:--:|
| IT-023 单实例申请时延 | `< 1s` | `24.85ms`，HTTP `200` | 通过 |
| IT-024 `200` 并发申请时延 | `< 1s` | avg `532ms` / P50 `579ms` / P95 `711ms` / Max `776ms`，失败 `0` | 通过 |
| IT-025 `1000` 实例拉起（5 轮） | 全部 `WarmReady` | `1000` 拉起 `52~56s`，单节点 CPU 峰值 `5.3~8.3C`（占比 `17%~26%`），稳态 `≈21.7Mi`/实例 | 通过 |
| IT-025 `warm=1000` 申请时延（5 轮） | `< 5s` | avg `1.40s` / P50 `1.95~1.97s` / P95 `2.00~2.01s` / P99 `2.02~2.04s` / Max `2.04~2.08s`，失败 `0` | 通过 |

**总结：`serverlessdb-IT-023`、`IT-024`、`IT-025` 全部通过验证——申请接口时延满足 `200` 并发 `< 1s`、`warm=1000` 规模 `< 5s` 目标（5 轮重复验证，P99 稳定在 `2.0s` 量级）；时延抬升源于 `200` 并发在 operator 入口的排队（operator 侧处理占比 `~100%`），扩容 operator 副本可线性改善；`1000` 实例拉起 `52~56s`、单节点资源余量充足，稳态约 `~4.6C/~21Gi`，千级规模资源与时延均不构成瓶颈。**
