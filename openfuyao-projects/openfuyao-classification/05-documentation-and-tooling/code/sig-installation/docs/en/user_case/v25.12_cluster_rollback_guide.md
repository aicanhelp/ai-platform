# v25.12 Cluster Rollback Guide

This guide explains how to restore node components and the management-plane `BKECluster` (bc for short) to the pre-upgrade state when an openFuyao **v25.12** baseline cluster fails a patch upgrade (example: `v25.12` → `v25.12.9`) or must be rolled back.

## Overview

Complete these steps in order: **pre-upgrade backup → node-side rollback → (if needed) management-plane bc recovery**:

| Step | What to do | Notes |
| --- | --- | --- |
| Preparation: pre-upgrade backup | etcd snapshot + static Pod manifests + node binaries | Rollback prerequisite; choose either the one-click script or manual backup |
| Phase 1: node-side rollback | Stop processes → etcd snapshot restore → static Pod manifests → roll back binaries → start services | All three etcd members must use the **same** snapshot |
| Phase 2: management-plane bc recovery | Only when a **business cluster** has been rolled back on nodes but bc on the management cluster is still in the upgraded state | Align bc `spec` / `status`; temporarily bypass the Validating Webhook when lowering k8s/etcd |

> ![Note](figures/icon-note.gif) **Note:**<br />If you are rolling back the **management cluster itself**, etcd restore also returns BKECluster, Provider, bkeagent-deployer, kube-proxy, and related objects in etcd to the snapshot time. You usually **do not** need to manually edit CRs or set images. If you are rolling back a **business cluster**, the management-cluster etcd is not restored, so you must run Phase 2 after the node-side rollback.

### Applicable scenarios

- Baseline: openFuyao **v25.12** (component baselines are listed in the “Rollback targets” table below)
- Pre-upgrade backups completed (etcd snapshot + static Pod manifests + node binaries)
- Need to roll back to the pre-upgrade version after a patch upgrade (target baseline: openFuyao **v25.12** / k8s `v1.34.3-of.1` / etcd `v3.6.7-of.1` / containerd `v2.1.1`)

### Rollback component overview

| Component | Rollback target (v25.12 baseline) | How to roll back |
| --- | --- | --- |
| cluster-api-provider-bke | 1.0.4 | Follows etcd data rollback (management-cluster self-rollback) |
| bkeagent-deployer | 1.0.4 | Follows etcd data rollback |
| kube-proxy | v1.34.3-of.1 | Follows etcd data rollback |
| etcd | v3.6.7-of.1; data from the pre-upgrade snapshot | Restore the same snapshot on all three masters; roll back manifests manually |
| kube-apiserver / controller-manager / scheduler | v1.34.3-of.1 | Roll back static Pod YAML manually |
| kubelet / kubectl | v1.34.3-of.1 | Roll back binaries manually (all nodes) |
| containerd (including shim, ctr, and config) | v2.1.1 | Roll back binaries + `/etc/containerd` manually |
| bkeagent | Pre-upgrade files | Roll back binary + systemd unit manually |

```bash
M1=192.168.200.xx    # Master / etcd member 2
M2=192.168.200.xx    # Master / etcd member 3

```

## Preparation: pre-upgrade backup (rollback prerequisite)

**Approach:** Take an etcd snapshot before the upgrade. During rollback, restore the **same** db on all three Masters so the API returns to the snapshot moment.

Run the backup on every node (3 Masters + Worker). Use either the **one-click script** or **manual backup**—**choose one**. Do not run 1.1 and then repeat 1.2.

### Confirm the etcd leader (which snapshot to use)

Either backup method produces a `pre-upgrade-*.db` on each Master. For restore, use **only one** of them. Prefer the **leader** snapshot confirmed before the upgrade (`IS LEADER` is `true`):

```bash
ETCDCTL_API=3 etcdctl endpoint status \
  --write-out=table \
  --endpoints=https://<M0>:2379,https://<M1>:2379,https://<M2>:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
```

Record the leader hostname/IP so you can later copy that node’s db to a common `restore.db`.

### 1.1 One-click backup script

Save the following script as `backup-pre-upgrade-v25.12.sh` and run it on **every node** (it already covers the etcd snapshot, static Pod manifests, and node binaries, so skip 1.2):

```bash
bash backup-pre-upgrade-v25.12.sh
# or: BAK=/root/upgrade-backup-v25.12.9 bash backup-pre-upgrade-v25.12.sh
```

```bash
#!/bin/bash
set -eu
unalias cp 2>/dev/null || true

BAK=${BAK:-/root/upgrade-backup-v25.12.9}
ETCD_CACERT=${ETCD_CACERT:-/etc/kubernetes/pki/etcd/ca.crt}
ETCD_CERT=${ETCD_CERT:-/etc/kubernetes/pki/etcd/server.crt}
ETCD_KEY=${ETCD_KEY:-/etc/kubernetes/pki/etcd/server.key}

HOST=$(hostname)
ROLE=worker
if [ -f /etc/kubernetes/manifests/etcd.yaml ]; then
  ROLE=master
fi

echo "==== backup start host=${HOST} role=${ROLE} bak=${BAK} ===="
mkdir -p "${BAK}/bin" "${BAK}/containerd" "${BAK}/bkeagent"

copy_if_exists() {
  src=$1
  dst=$2
  if [ -e "$src" ]; then
    cp -af "$src" "$dst"
    echo "copied $src -> $dst"
  else
    echo "skip (missing) $src"
  fi
}

copy_if_exists /usr/bin/kubelet "${BAK}/bin/kubelet"
copy_if_exists /usr/bin/kubectl "${BAK}/bin/kubectl"
command -v kubelet >/dev/null 2>&1 && kubelet --version | tee "${BAK}/bin/kubelet.version"

copy_if_exists /usr/bin/containerd "${BAK}/bin/containerd"
copy_if_exists /usr/bin/containerd-shim-runc-v2 "${BAK}/bin/containerd-shim-runc-v2"
copy_if_exists /usr/bin/ctr "${BAK}/bin/ctr"
if [ -d /etc/containerd ]; then
  rm -rf "${BAK}/containerd/etc-containerd"
  cp -a /etc/containerd "${BAK}/containerd/etc-containerd"
fi
command -v containerd >/dev/null 2>&1 && containerd --version | tee "${BAK}/bin/containerd.version"

copy_if_exists /etc/bkeagent/bin/bkeagent "${BAK}/bkeagent/bkeagent"
copy_if_exists /usr/local/bin/bkeagent "${BAK}/bkeagent/bkeagent.usr-local"
copy_if_exists /etc/systemd/system/bkeagent.service "${BAK}/bkeagent/bkeagent.service"

etcd_snapshot_save() {
  db=$1
  if command -v etcdctl >/dev/null 2>&1; then
    ETCDCTL_API=3 etcdctl snapshot save "$db" \
      --endpoints=https://127.0.0.1:2379 \
      --cacert="$ETCD_CACERT" --cert="$ETCD_CERT" --key="$ETCD_KEY"
    return 0
  fi
  cid=$(crictl ps -q --name etcd 2>/dev/null | head -n1)
  [ -n "$cid" ] || { echo "ERROR: etcd container not found" >&2; return 1; }
  crictl exec "$cid" etcdctl snapshot save /tmp/pre-upgrade.db \
    --endpoints=https://127.0.0.1:2379 \
    --cacert="$ETCD_CACERT" --cert="$ETCD_CERT" --key="$ETCD_KEY"
  crictl cp "$cid":/tmp/pre-upgrade.db "$db"
}

if [ "$ROLE" = master ]; then
  mkdir -p "${BAK}/etcd" "${BAK}/manifests"
  db="${BAK}/etcd/pre-upgrade-${HOST}.db"
  etcd_snapshot_save "$db"
  command -v etcdctl >/dev/null 2>&1 && ETCDCTL_API=3 etcdctl snapshot status "$db" --write-out=table || true
  grep -E 'initial-cluster|initial-cluster-token|advertise-peer-urls|--name=' \
    /etc/kubernetes/manifests/etcd.yaml > "${BAK}/etcd/etcd-cluster-args.txt" || true
  for f in etcd.yaml kube-apiserver.yaml kube-controller-manager.yaml kube-scheduler.yaml; do
    copy_if_exists "/etc/kubernetes/manifests/${f}" "${BAK}/manifests/${f}"
  done
fi

echo "==== backup done ${HOST} ===="
find "${BAK}" -type f | sort
```

### 1.2 Manual backup (alternative to 1.1)

Use the steps below only when you did **not** use the one-click script. Nodes that already ran 1.1 should **skip this section**.

**etcd (every Master):** Take one snapshot per Master while the cluster is healthy. For which copy to use during rollback, see “Confirm the etcd leader” above.

```bash
mkdir -p ${BAK}/etcd
ETCDCTL_API=3 etcdctl snapshot save ${BAK}/etcd/pre-upgrade-$(hostname).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

grep -E 'initial-cluster|initial-cluster-token|advertise-peer-urls|--name=' \
  /etc/kubernetes/manifests/etcd.yaml | tee ${BAK}/etcd/etcd-cluster-args.txt
```

**Static Pod manifests (every Master):**

```bash
mkdir -p ${BAK}/manifests
cp -a /etc/kubernetes/manifests/etcd.yaml \
      /etc/kubernetes/manifests/kube-apiserver.yaml \
      /etc/kubernetes/manifests/kube-controller-manager.yaml \
      /etc/kubernetes/manifests/kube-scheduler.yaml \
      ${BAK}/manifests/
```

**kubelet / kubectl / containerd / bkeagent (all nodes):**

```bash
mkdir -p ${BAK}/bin ${BAK}/containerd ${BAK}/bkeagent
\cp -af /usr/bin/kubelet /usr/bin/kubectl ${BAK}/bin/
\cp -af /usr/bin/containerd /usr/bin/containerd-shim-runc-v2 /usr/bin/ctr ${BAK}/bin/
cp -a /etc/containerd ${BAK}/containerd/etc-containerd
\cp -af /etc/bkeagent/bin/bkeagent ${BAK}/bkeagent/bkeagent 2>/dev/null || true
\cp -af /usr/local/bin/bkeagent ${BAK}/bkeagent/bkeagent.usr-local 2>/dev/null || true
\cp -af /etc/systemd/system/bkeagent.service ${BAK}/bkeagent/ 2>/dev/null || true
```

Expected baseline: `kubelet --version` → `v1.34.3-of.1`; `containerd --version` → `v2.1.1`.

## Phase 1: Node-side rollback

> ![Danger](figures/icon-danger.gif) **Danger:**<br />This section stops the control plane, relocates `/var/lib/etcd`, and rebuilds the etcd data directory from a snapshot. The operation is irreversible. All three Masters must use the **same** snapshot. If any step fails, restore the post-upgrade state first using the principles below, then investigate.

Principles:

1. **Stop all three etcd members together** and restore the same snapshot; do not restore only one member.
2. Order: **restore etcd → restore static Pod manifests → replace binaries → start only when everything is ready**. Do not start the old kubelet before restore.
3. If any restore fails: on all three masters, move `/var/lib/etcd.upgraded-*` back to `/var/lib/etcd`, put `etcd.yaml.bak` back into manifests, and restore the post-upgrade state first.

Recommended sequence:

```text
1. Stop kubelet on all nodes; on Masters, also stop leftover etcd/apiserver containers
2. Restore the same snapshot on all three Masters
3. Restore the four backed-up static Pod manifests on all three Masters
4. On all nodes: stop containerd / shim / bkeagent and restore the old binaries
5. Reserve port 58080; start containerd, then kubelet, then bkeagent
6. Wait until the 3-member etcd is healthy and the API is ready
```

### 2.1 Stop processes

On all nodes:

```bash
systemctl stop kubelet
```

Then on all three Masters:

```bash
for cname in etcd kube-apiserver kube-controller-manager kube-scheduler; do
  cid=$(crictl ps -q --name "$cname" 2>/dev/null)
  [ -n "$cid" ] && crictl stop "$cid"
done
mv /etc/kubernetes/manifests/etcd.yaml /root/etcd.yaml.bak
sleep 5
crictl ps | grep -E 'etcd|kube-apiserver' || true
```

Restore only after no etcd container remains on any of the three Masters.

### 2.2 All Masters: restore the same etcd snapshot

> ![Danger](figures/icon-danger.gif) **Danger:**<br />After `mv /var/lib/etcd`, the previous member data directory is no longer the active data dir. All three hosts must restore the **same** db, and `--initial-cluster-token` must use a **new value**. Incorrect parameters can prevent membership formation or cause data inconsistency.

1. Copy the **leader (recommended)** `pre-upgrade-*.db` to all three Masters at a common path such as `${BAK}/etcd/restore.db`. Confirm the leader with `etcdctl endpoint status` (see [Confirm the etcd leader](#confirm-the-etcd-leader-which-snapshot-to-use)).
2. Fill restore parameters from each host’s `${BAK}/etcd/etcd-cluster-args.txt` (for YAML lines like `- --foo=bar`, take only `bar`).
3. `--initial-cluster` must be the **same string** on all three hosts; `--initial-cluster-token` must be the same on all three and use a **new value** (for example `rollback-20260827`).
4. `--name` and `--initial-advertise-peer-urls` must follow **each host’s own yaml**—do not set all three to M0.

M0 example:

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
mv /var/lib/etcd /var/lib/etcd.upgraded-${STAMP}
mkdir -p /var/lib/etcd

ETCDCTL_API=3 etcdctl snapshot restore ${BAK}/etcd/restore.db \
  --data-dir=/var/lib/etcd \
  --name=m1 \
  --initial-cluster=m1=https://<M0>:2380,m2=https://<M1>:2380,m3=https://<M2>:2380 \
  --initial-cluster-token=rollback-20260827 \
  --initial-advertise-peer-urls=https://<M0>:2380
```

On M1 / M2, restore the **same** `restore.db` and change only `--name` and `--initial-advertise-peer-urls`.

Success indicators: logs show `restored snapshot`, and these paths exist:

```bash
ls /var/lib/etcd/member/wal /var/lib/etcd/member/snap
```

### 2.3 All Masters: restore static Pod manifests

After a successful restore and **before** starting kubelet:

```bash
\cp -af ${BAK}/manifests/*.yaml /etc/kubernetes/manifests/
grep 'image:' /etc/kubernetes/manifests/*.yaml
```

Expected image tags: etcd `3.6.7-of.1`, control plane `1.34.3-of.1`. Do not overwrite the entire `/etc/kubernetes` directory.

### 2.4 All nodes: roll back binaries

> ![Warning](figures/icon-warning.gif) **Warning:**<br />Stop related processes cleanly before overwriting binaries. `pkill -9` forcibly terminates matching processes—confirm the path match is correct to avoid killing unrelated processes.

Stop cleanly before overwriting (`pkill` needs `-f` for long path matches):

```bash
systemctl stop kubelet
systemctl stop containerd
systemctl stop bkeagent 2>/dev/null || true
pkill -9 -f '/usr/bin/containerd-shim-runc-v2' || true
pkill -9 -f '/usr/local/bin/bkeagent' || true
pkill -9 -f '/etc/bkeagent/bin/bkeagent' || true
sleep 2
```

Then copy back:

```bash
\cp -af ${BAK}/bin/containerd ${BAK}/bin/containerd-shim-runc-v2 ${BAK}/bin/ctr /usr/bin/
\cp -af ${BAK}/containerd/etc-containerd/. /etc/containerd/
\cp -af ${BAK}/bin/kubelet ${BAK}/bin/kubectl /usr/bin/
chmod 755 /usr/bin/kubelet /usr/bin/kubectl /usr/bin/containerd
containerd --version   # v2.1.1
kubelet --version      # v1.34.3-of.1

\cp -af ${BAK}/bkeagent/bkeagent /etc/bkeagent/bin/bkeagent
chmod 755 /etc/bkeagent/bin/bkeagent
\cp -af ${BAK}/bkeagent/bkeagent.usr-local /usr/local/bin/bkeagent 2>/dev/null || true
\cp -af ${BAK}/bkeagent/bkeagent.service /etc/systemd/system/bkeagent.service 2>/dev/null || true
```

Confirm with md5 that the running binaries match the backup:

```bash
md5sum ${BAK}/bin/kubelet /usr/bin/kubelet
md5sum ${BAK}/bin/containerd /usr/bin/containerd
md5sum ${BAK}/bkeagent/bkeagent /etc/bkeagent/bin/bkeagent
```

Before starting kubelet, reserve local port **58080** on all nodes so apiserver↔etcd traffic does not block bkeagent listening:

```bash
cur=$(sysctl -n net.ipv4.ip_local_reserved_ports)
if ! echo ",${cur}," | grep -q ',58080,'; then
  if [ -z "$cur" ]; then
    sysctl -w net.ipv4.ip_local_reserved_ports=58080
  else
    sysctl -w net.ipv4.ip_local_reserved_ports="${cur},58080"
  fi
fi
echo "net.ipv4.ip_local_reserved_ports = $(sysctl -n net.ipv4.ip_local_reserved_ports)" \
  > /etc/sysctl.d/99-bkeagent-health.conf
```

Then start services:

```bash
systemctl daemon-reload
systemctl start containerd
systemctl start kubelet
systemctl start bkeagent
systemctl is-active containerd kubelet bkeagent
ss -tlnp | grep 58080
```

If 58080 is still in use (existing ESTAB connections):

```bash
ss -K -t -n sport = :58080 dport = :2379
ss -K -t -n sport = :2379 dport = :58080
systemctl reset-failed bkeagent
systemctl start bkeagent
```

If that still fails, restart only **this node’s** kube-apiserver static Pod (do not touch etcd):

```bash
mv /etc/kubernetes/manifests/kube-apiserver.yaml /tmp/kube-apiserver.yaml
sleep 8
mv /tmp/kube-apiserver.yaml /etc/kubernetes/manifests/
systemctl start bkeagent
```

kubelet on all three Masters must come up within a short window so etcd can form a 3-member cluster.

### 2.5 Verify node-side rollback

Confirm components are back on the v25.12 baseline:

| Check | Expected |
| --- | --- |
| etcd members | 3 members healthy |
| Static Pod images | etcd `3.6.7-of.1`; control plane `1.34.3-of.1` |
| kubelet / kubectl | `v1.34.3-of.1` |
| containerd | `v2.1.1` |
| bkeagent | Listening on `:58080` |
| (management-cluster self-rollback) bc | Version and health state match the snapshot |

```bash
# etcd (any Master)
ETCDCTL_API=3 etcdctl endpoint health \
  --endpoints=https://<M0>:2379,https://<M1>:2379,https://<M2>:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# Static Pod images (Master)
grep 'image:' /etc/kubernetes/manifests/*.yaml

# Node binaries (all nodes)
kubelet --version
containerd --version
ss -tlnp | grep 58080

# Management-cluster self-rollback: bc status
kubectl get bc -A -o wide
```

## Phase 2: Restore management-plane BKECluster after workload-cluster rollback

Use this when **workload-cluster nodes were rolled back in Phase 1**, but the management cluster did not restore etcd and bc still shows `Upgrading` / `UpgradeFailed` (`clusterHealthState` may still be `Healthy`).

Recovery principles:

1. **status can be patched directly** to restore `Healthy` / `Ready` and version display.
2. **spec must match the business cluster’s actual versions**; otherwise unpausing may trigger another upgrade.
3. The Validating Webhook **rejects** k8s / etcd downgrades by default. When you must lower `kubernetesVersion` / `etcdVersion`, temporarily bypass it and restore it immediately afterward.

### 3.1 Preconditions

```bash
export NS=<bc-namespace>
export BC=<bc-name>

kubectl get bc "$BC" -n "$NS" -o wide
kubectl get bc "$BC" -n "$NS" -o jsonpath='spec: {.spec.clusterConfig.cluster.openFuyaoVersion}/{.spec.clusterConfig.cluster.kubernetesVersion}/{.spec.clusterConfig.cluster.etcdVersion}/{.spec.clusterConfig.cluster.containerdVersion}{"\n"}status: {.status.openFuyaoVersion}/{.status.kubernetesVersion}/{.status.etcdVersion}/{.status.containerdVersion}{"\n"}health: {.status.clusterHealthState}/{.status.clusterStatus}{"\n"}'
```

Record the post-rollback targets (must match the nodes), for example:

| Field | v25.12 baseline |
| --- | --- |
| `openFuyaoVersion` | `v25.12` |
| `kubernetesVersion` | `v1.34.3-of.1` |
| `etcdVersion` | `v3.6.7-of.1` |
| `containerdVersion` | `v2.1.1` |

Backup:

```bash
kubectl get bc "$BC" -n "$NS" -o yaml > bc-before-recovery.yaml
kubectl get bkenode -n "$NS" -l cluster.x-k8s.io/cluster-name="$BC" -o yaml > bkenode-before-recovery.yaml 2>/dev/null || true
kubectl get validatingwebhookconfiguration bke-validating-webhook-configuration -o yaml > vwc-backup.yaml
```

### 3.2 Pause reconciliation and clear annotations

```bash
kubectl patch bc "$BC" -n "$NS" --type merge -p '{"spec":{"pause":true}}'
kubectl annotate bc "$BC" -n "$NS" bke.bocloud.com/retry- 2>/dev/null || true
```

### 3.3 Restore bc status

```bash
kubectl patch bc "$BC" -n "$NS" --subresource=status --type merge -p "{
  \"status\": {
    \"openFuyaoVersion\": \"<post-rollback-openFuyao-version>\",
    \"kubernetesVersion\": \"<post-rollback-k8s-version>\",
    \"etcdVersion\": \"<post-rollback-etcd-version>\",
    \"containerdVersion\": \"<post-rollback-containerd-version>\",
    \"clusterHealthState\": \"Healthy\",
    \"clusterStatus\": \"Ready\"
  }
}"
```

### 3.4 Restore bc spec

**Only openFuyao / containerd need rollback** (k8s / etcd unchanged): patch directly; no webhook bypass required.

**When kubernetesVersion / etcdVersion must be lowered**:

> ![Warning](figures/icon-warning.gif) **Warning:**<br />Temporarily bypassing the Validating Webhook weakens version-downgrade checks. **After bypassing, patch spec immediately and restore the webhook at once.** Do not leave the bypass in place.

1. Back up the VWC (see above).
2. Confirm the index of `vbkecluster.kb.io` (**not necessarily 0**):

```bash
kubectl get validatingwebhookconfiguration bke-validating-webhook-configuration \
  -o jsonpath='{range .webhooks[*]}{.name}{"\n"}{end}' | nl -v 0
```

3. Temporarily bypass validation (replace `<N>` with the actual index):

```bash
kubectl patch validatingwebhookconfiguration bke-validating-webhook-configuration --type json -p '[
  {
    "op": "add",
    "path": "/webhooks/<N>/objectSelector",
    "value": {
      "matchLabels": {
        "openfuyao.cn/temp-force-validate": "true"
      }
    }
  }
]'
```

4. Patch spec immediately:

```bash
kubectl patch bc "$BC" -n "$NS" --type merge -p "{
  \"spec\": {
    \"clusterConfig\": {
      \"cluster\": {
        \"openFuyaoVersion\": \"<post-rollback-openFuyao-version>\",
        \"kubernetesVersion\": \"<post-rollback-k8s-version>\",
        \"etcdVersion\": \"<post-rollback-etcd-version>\",
        \"containerdVersion\": \"<post-rollback-containerd-version>\"
      }
    }
  }
}"
```

5. **Restore the webhook immediately** (do not `kubectl apply` a backup that still has an old `resourceVersion`; that often causes Conflict):

```bash
kubectl patch validatingwebhookconfiguration bke-validating-webhook-configuration --type json -p '[
  {"op":"remove","path":"/webhooks/<N>/objectSelector"}
]'
# or: kubectl replace --force -f vwc-backup.yaml
```

### 3.5 Restore BKENode (if present)

When BKENode is split out in v25.12:

```bash
kubectl get bkenode -n "$NS" -l cluster.x-k8s.io/cluster-name="$BC" \
  -o custom-columns=NAME:.metadata.name,IP:.spec.ip,STATE:.status.state

kubectl patch bkenode <node-name> -n "$NS" --subresource=status --type merge -p '{
  "status": {"state": "Ready", "message": ""}
}'
```

### 3.6 Unpause and observe

```bash
kubectl get validatingwebhookconfiguration bke-validating-webhook-configuration \
  -o jsonpath='{range .webhooks[?(@.name=="vbkecluster.kb.io")]}{.name} objectSelector={.objectSelector}{"\n"}{end}'

kubectl patch bc "$BC" -n "$NS" --type merge -p '{"spec":{"pause":false}}'
kubectl get bc "$BC" -n "$NS" -w
```

Expected: `clusterHealthState=Healthy`, `clusterStatus=Ready`, `spec`/`status` versions match the nodes, and BKENode is `Ready`.

## Checklist

```text
[Before upgrade]
□ Back up all nodes: one-click script (1.1) or manual backup (1.2), choose one
□ Confirm the etcd leader and record which snapshot will be used for restore
□ Confirm backed-up binary versions match the v25.12 baseline

[Node-side rollback]
□ Stop kubelet everywhere; on Masters, stop etcd/control-plane containers
□ Restore the same snapshot on all three Masters
□ Restore static Pod manifests
□ Roll back containerd / kubelet / kubectl / bkeagent binaries
□ Reserve 58080; start containerd → kubelet → bkeagent
□ Verify etcd / control plane / binary versions

[Business cluster: management-plane bc recovery]
□ Confirm the real node versions
□ Pause bc; clear the retry annotation
□ Patch status → Healthy/Ready
□ Align spec (temporarily bypass the webhook when lowering k8s/etcd; restore it immediately)
□ Restore BKENode (if present)
□ Unpause and observe for 5–10 minutes
```

## FAQ

| Symptom | Action |
| --- | --- |
| Restored only one etcd member | Not allowed; all three must use the same snapshot and the same new token |
| Restore failed | Roll `/var/lib/etcd.upgraded-*` back on all three Masters, restore the post-upgrade state, then investigate |
| bkeagent `58080 already in use` | Reserve the port + `ss -K` to drop ESTAB; restart this node’s apiserver static Pod if needed |
| bc becomes `Upgrading` again after patch | spec is still higher than the actual version; pause again and realign |
| spec downgrade rejected | Bypass `vbkecluster.kb.io` as in 3.4, patch, then restore the webhook immediately |
| `kubectl apply -f vwc-backup.yaml` Conflict | Remove `objectSelector` with patch, or `kubectl replace --force -f vwc-backup.yaml` |
