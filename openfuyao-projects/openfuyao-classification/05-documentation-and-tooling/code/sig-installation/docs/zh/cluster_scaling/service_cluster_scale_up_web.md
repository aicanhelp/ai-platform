# 通过前台（Web页面）扩容业务集群

集群扩容是指在已有业务集群的基础上，向集群中新增工作节点（Worker Node），以提升集群的计算资源和调度能力。通过openFuyao管理面的集群生命周期管理页面，用户可以方便地在Web界面上完成业务集群的扩容操作。

## 前提条件

- 待扩容的业务集群状态为“健康”。在集群生命周期管理列表界面可查看集群状态，详情请参见[管理面安装业务集群](../cluster_installation_guide/service_cluster_installation/service_cluster_installation_on_the_management_plane.md)。
- 需在创建该集群时使用的引导节点或管理集群上进行扩容操作。

> ![输入图片说明](figures/icon-notice.gif) **须知：**
> 集群扩容操作必须在创建该集群时使用的引导节点或管理集群上进行，否则无法管理目标集群。

- 已准备好待加入集群的新节点，且节点满足以下要求：
  - 节点可以连通管理集群网络。
  - 节点可以使用root用户通过SSH登录。
  - 节点为裸机操作系统，未安装任何docker与Kubernetes组件。
  - 节点的IP地址未被任何已有集群使用。
  - 节点的时间与管理集群时间差不超过10秒。

## 使用限制

- 扩容时仅支持添加工作节点（Worker Node），不支持通过Web页面新增Master节点。
- 扩容时需确保使用的节点是未被使用的，避免IP冲突或环境冲突导致扩容失败。
- 当前仅支持IPv4地址的节点。
- 集群处于扩容、安装、升级等非稳定状态时，不允许发起新的扩容操作。

## 操作步骤

1. 登录创建该集群时使用的引导节点或管理集群的openFuyao管理面。

   浏览器中输入“https://<引导节点或管理集群的登录IP地址>:<集群生命周期管理的web服务端口>”，输入用户名和密码登录集群生命周期管理页面。

   > ![输入图片说明](figures/icon-note.gif) **说明：**
   > - 通过引导节点登录时，Web服务端口默认为30010；通过管理集群登录时，web服务端口默认为31616。

2. 在openFuyao平台的左侧导航栏中选择“集群生命周期管理”。界面展示集群生命周期管理的列表信息，包括“集群名称”、“状态”、“节点数”等信息。

3. 在“集群生命周期管理”列表界面单击需要扩容的“集群名称”，进入“节点详情”界面。

   > ![输入图片说明](figures/icon-note.gif) **说明：**
   > 节点详情界面的节点列表信息按照Master节点在前，Worker在后的顺序排列。

4. 在节点列表信息的右上方单击“+ 新增节点”，弹出“新增节点”窗口。

5. 在“新增节点”窗口中填写待扩容节点的信息。

   **表 1** 节点信息说明

   | 参数名称 | 说明 |
   |:---------- |:------- |
   | 节点名称 | 新增节点的hostname。需符合Kubernetes命名规范：小写字母、数字和连字符（-），长度1~63个字符，不能为纯数字。 |
   | IP地址 | 新增节点的IP地址，需为有效的IPv4地址，且未被任何集群使用。 |
   | 端口号 | SSH登录端口号，默认为22，取值范围0~65535。 |
   | 用户名 | SSH登录用户名，默认为root。 |
   | 密码 | SSH登录密码。 |

   - 单击“添加新节点”可继续增加节点行。
   - 单击“操作”列的删除图标可删除已添加的节点行，至少保留一行。

6. 单击“一键校验”，系统将校验所有新增节点的信息。

   校验内容包括：
   - 节点IP地址在所有集群中是否唯一。
   - 节点名称在目标集群中是否唯一。
   - 节点是否可通过SSH连通。
   - 节点与管理集群的时间差是否在允许范围内（不超过10秒）。
   - 如果为高可用集群，还会校验负载均衡器IP是否可用。

   > ![输入图片说明](figures/icon-note.gif) **说明：**
   > - 校验成功后，提示“一键校验成功，请创建”，“确定”按钮变为可用状态。
   > - 校验失败时，提示错误信息，且对应节点的IP地址行会标红显示。请根据错误信息修正节点信息后重新校验。
   > - 节点信息变更后需重新执行“一键校验”。

7. 校验通过后，单击“确定”。

   系统下发扩容任务，弹出“集群信息”日志窗口，实时展示扩容操作日志。

8. 待日志滚动完成后，单击“退出日志”。返回集群生命周期管理列表界面，对应集群的“状态”列显示为“安装中”。

   > ![输入图片说明](figures/icon-note.gif) **说明：**
   > 扩容过程中，集群状态会在“安装中”和“扩容中”之间切换。“安装中”对应推送bkeagent、节点环境准备和后置处理阶段；“扩容中”对应工作节点加入集群阶段。

9. 待“状态”列字段更新完毕，完成集群扩容。

   - 扩容成功：对应集群的“状态”列为“健康”。
   - 扩容失败：对应集群的“状态”列为“扩缩容失败”。

> ![输入图片说明](figures/icon-note.gif) **说明：**
> 在扩容未完成时，集群尚未稳定，请勿对集群进行其他操作。

## 状态说明

扩容过程中，集群状态变化如下：

| 状态 | 说明 |
|:----- |:----------- |
| 安装中 | 推送bkeagent代理到新节点、节点环境初始化（安装containerd等组件）、后置脚本处理阶段。 |
| 扩容中 | 工作节点正在执行kubeadm join，加入业务集群。 |
| 扩缩容失败 | 扩容过程中出现错误，节点未能成功加入集群。需要排查后重试。 |
| 健康 | 扩容完成，所有新增节点已就绪，集群处于健康状态。 |

> ![输入图片说明](figures/icon-notice.gif) **须知：**
> 扩容失败后，集群状态显示为“扩缩容失败”"。请参考[集群部署问题定位指导](../cluster_installation_guide/appendix/cluster_deployment_issue_diagnosis_guide.md)排查原因。

## 后续操作

完成集群扩容后，如需对集群进行缩容操作，请参见[通过前台（Web页面）缩容业务集群](./service_cluster_scale_down_web.md)。
