## 1、特性描述

### 特性概述

为 bkeadm 补丁包构建引入 OCI (Open Container Initiative) 标准镜像同步策略，**解决 CI/CD 流水线中 Docker-in-Docker (DinD) 问题**，实现无需 Docker 环境的补丁包构建。

**实现功能**:
1. 离线补丁包构建：`bke build patch -f patchV1.yaml -t patchV1.tar.gz --strategy=oci`
2. 离线补丁包部署：`bke registry patch --source ./patchV1 --target 0.0.0.0:40443`（自动检测 OCI 格式）
3. 格式自动检测：支持 OCI 和 Registry 两种格式的补丁包
4. 统一镜像复制接口：`reg.CopyRegistry()` 支持所有 transport 类型

### 3.2、模块设计

#### 3.2.1 构建阶段功能模块

##### 模块 1: 策略选择与环境检查 (`pkg/build/patch.go`)

**功能描述**: 根据用户指定的策略参数，决定是否需要 Docker 环境

**详细步骤**:
1. 读取命令行参数 `--strategy`
2. 验证策略值（registry 或 oci）
3. 如果是 OCI 策略，跳过 Docker 环境检查
4. 如果是 Registry 策略，执行 `infrastructure.IsDocker()` 检查


##### 模块 2: 镜像同步策略路由 (`pkg/build/patch.go`)

**功能描述**: 根据策略类型调用不同的镜像同步函数

**详细步骤**:
1. 检查策略类型
2. OCI 策略：跳过 `buildRegistry()`（不启动 Registry 容器）+调用 `syncRepoOCI()`
3. Registry 策略：调用 `buildRegistry()` + `syncRepo()`


##### 模块 3: OCI Layout 结构创建 (`pkg/build/ocisyncimage.go`)

**功能描述**: 创建符合 OCI 标准的目录结构

**详细步骤**:
1. 创建临时目录 `tmpRegistry/oci-layout/`
2. 创建 `blobs/sha256/` 目录（存储镜像层和 manifest）
3. 创建 `oci-layout` 文件（版本声明）
4. 内容：`{"imageLayoutVersion":"1.0.0"}`
5. 最终移动到 `volumes/oci-layout/`


**OCI Layout 目录结构**:
```
volumes/oci-layout/
├── oci-layout              # 版本声明文件
├── index.json              # 镜像索引（自动生成）
└── blobs/
    └── sha256/
        ├── <digest1>       # 镜像 manifest
        ├── <digest2>       # 镜像配置
        └── <digest3>       # 镜像层
```

##### 模块 4: 镜像同步到 OCI Layout (`pkg/build/ocisyncimage.go`)

**功能描述**: 遍历配置文件中的镜像列表，同步到 OCI Layout

**详细步骤**:
1. 调用 `countTotalImages()` 计算总镜像数量
2. 使用 `syncContext` 封装上下文参数（进度跟踪）
3. 遍历层级：Repos → SubImages → Images → Tags
4. 对每个镜像：
   - 调用 `imageTrack()` 计算源镜像地址
   - 处理架构标记（单架构/多架构）
   - 格式化 OCI 引用名：`targetRepo/imageName:tag`
   - 调用 `syncImageToOCI()` 执行同步
5. 所有镜像共享同一个 OCI Layout（共享 blobs 目录）
6. 支持 stopChan 中断机制


##### 模块 5: 镜像复制核心逻辑 (`pkg/build/ocisyncimage.go`)

**功能描述**: 使用统一的 `reg.CopyRegistry()` 复制镜像到 OCI Layout

**详细步骤**:
1. 构建源镜像引用（`docker://...`）
2. 构建目标 OCI 引用（`oci:ociLayoutDir:imageRef`）
3. 调用 `reg.CopyRegistry()` 统一接口：
   - 自动处理 transport 前缀（docker://, oci:, dir: 等）
   - 配置 SystemContext（User-Agent: `bke/v1.0.0`）
   - 配置 TLS 验证选项
   - 设置架构选择（多架构支持）
4. **关键特性**：
   - 多架构（arch=""）：自动使用 `copy.CopyAllImages`
   - 单架构：使用 `copy.CopySystemImage`
   - 内置重试机制（最多 9 次）
   - 支持所有 containers/image 的 transport 类型
5. **多架构检测优化**：
   - 使用 `reg.IsMultiArchManifests()` 预先检测
   - 避免盲目尝试复制多架构镜像
   - 提高单架构镜像的复制效率

#### 3.2.2 部署阶段功能模块

##### 模块 6: OCI 格式检测 (`pkg/build/ociloader.go`)

**功能描述**: 检测补丁包是 OCI 格式还是 Registry 格式

**详细步骤**:
1. 检查 `volumes/oci-layout/` 目录是否存在
2. 调用 `isValidOCILayout()` 验证：
   - 检查 `oci-layout` 文件
   - 检查 `index.json` 文件
   - 检查 `blobs/sha256/` 目录
   - 验证 `oci-layout` 包含 `imageLayoutVersion`
3. 返回格式类型：`"oci"` 或 `"registry"`


##### 模块 7: OCI 镜像导入到 Registry (`pkg/build/patchsyncimage.go`)

**功能描述**: 从 OCI Layout 读取镜像并推送到目标 Registry

**详细步骤**:
1. 检测到 OCI 格式后，读取 `manifests.yaml`
2. 遍历镜像配置
3. 对每个镜像：
   - 构建 OCI 源引用：`oci:ociLayoutDir:imageRef`
   - 构建 Docker 目标引用：`docker://registry/image:tag`
   - 调用 `copyImageFromOCI()` → `reg.CopyRegistry()` 复制
4. 支持多架构镜像（根据 `opts.MultiArch` 参数）


### 3.2.3 模块接口定义

#### 接口 1: syncRepoOCI

```go
// OCI 策略主函数
func syncRepoOCI(cfg *BuildConfig, stopChan chan struct{}) error
// 功能：创建 OCI Layout 并同步所有镜像
// 调用者：pkg/build/patch.go:Patch()
```

#### 接口 2: syncImageToOCI

```go
// 同步单个镜像到 OCI Layout
func syncImageToOCI(
    sourceImage string,   // 源镜像地址
    ociLayoutDir string,  // OCI Layout 根目录
    imageRef string,      // 镜像引用名
    arch string,          // 架构（空=多架构）
    srcTLSVerify bool,    // TLS 验证
) error
// 功能：使用 containers/image 复制镜像
// 调用者：syncRepoOCI()
```

#### 接口 3: DetectPatchFormat

```go
// 检测补丁包格式
func DetectPatchFormat(source string) string
// 返回："oci" | "registry" | "unknown"
// 调用者：部署阶段
```

#### 接口 4: reg.CopyRegistry（统一镜像复制接口）

```go
// 统一的镜像复制接口（支持所有 transport）
func CopyRegistry(op Options) error
// 参数：
//   - Source: 源引用（自动处理前缀）
//   - Target: 目标引用（自动处理前缀）
//   - Arch: 架构（空=多架构）
//   - MultiArch: 是否多架构
//   - SrcTLSVerify: 源 TLS 验证
//   - DestTLSVerify: 目标 TLS 验证
// 功能：
//   - 自动检测并添加 transport 前缀
//   - 支持 docker://, oci:, dir:, docker-archive: 等
//   - 内置重试机制（9次）
//   - 统一的错误处理
// 调用者：ocisyncimage.go, patchsyncimage.go, registrysyncimage.go
```

#### 接口 5: reg.IsMultiArchManifests

```go
// 检测镜像是否为多架构 manifest
func IsMultiArchManifests(tlsVerify bool, imageAddress string) bool
// 功能：预先检测镜像是否为多架构，避免盲目尝试
// 调用者：ocisyncimage.go:syncImageToOCI()
// 优势：提高单架构镜像的复制效率
```


### 3.4、质量属性设计

#### 3.4.1、可靠性设计

-  重试机制（Registry 策略 9 次，OCI 策略继承）
-  断点续传（containers/image 特性）
-  清晰错误提示
-  统一的错误处理逻辑

#### 3.4.2、安全/韧性/隐私设计

-  TLS 证书验证
-  SHA256 完整性校验
-  文件权限控制（0755/0644）
-  User-Agent 仅含工具信息

#### 3.4.3、兼容性设计

-  完全向后兼容 Registry 策略
-  工具链兼容（skopeo, crane）
-  符合 OCI 标准
