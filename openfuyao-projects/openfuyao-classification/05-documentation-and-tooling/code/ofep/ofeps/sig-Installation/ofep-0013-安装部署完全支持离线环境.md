## 动机
<!--
本节用于明确列出该oFEP的动机、目标和非目标。描述变更的重要性以及对用户的好处。
-->

openFuyao现有功能无法完全支持离线安装功能，部分组件安装使用的镜像需要从第三方镜像源（比如docker.io）在线下载。

从已有的安装流程来看，存在**核心问题**：扩展组件安装过程中业务集群的containerd会从在线的第三方镜像源拉取镜像。

此外还有部分可优化点如下：

1. 镜像下载没法按照“组件”粒度控制，下载过程中容易多下载或者漏下载；
2. chart包是基于打包好的文件，没法做到实时下载最新的chart包文件；
3. 未提供组件的增量补丁安装功能。

“安装部署完全支持离线环境”需求旨在完全实现离线安装部署，提供完善的离线制品包制备流程，提前下载好组件安装所依赖的全部镜像，安装过程中先将其导入到引导节点启动的Registry镜像源服务，安装过程中设置业务集群containerd的重定向，做到组件安装所需的镜像均来源于引导节点的Registry服务，实现完全离线安装部署。此外还提供组件的增量补丁安装，实现已有组件的镜像更新和新组件的安装。

### 目标
<!--

1. 能够按“组件”粒度控制镜像的下载，外加实时下载最新的chart包文件；
2. 业务集群配置containerd的重定向能力；
3. 支持组件的增量和补丁安装。

### 方案介绍

#### 优化制备流程

#### 组件粒度控制镜像下载，实时下载最新的chart包文件

1. 优化点：按照“组件”粒度控制镜像的下载；
2. 新增点：新增实时下载最新chart包文件。

yaml配置文件举例如下：

   ```yaml
   repos: # 优化
     - architecture:  # openfuyao volcano扩展组件
         - amd64
         - arm64
       needDownload: true # 控制组件镜像是否需预下载，true-需下载，false-不下载   新增
       subImages:
         - sourceRepo: harbor.openfuyao.com/openfuyao   # 来源1
           targetRepo: openfuyao
           images:
             - name: volcano-config-website
               tag:
                 - latest
         - sourceRepo: docker.io   # 来源2
           targetRepo: /
           images:
             - name: volcanosh/vc-webhook-manager
               tag:
                 - v1.9.0
   rpms:
   debs: []
   files:
   charts: # chart包  新增，用于实时下载最新的chart包文件
     - address: https://harbor.openfuyao.com/chartrepo/openfuyao-catalog-pre/charts/
       files:
         - volcano-config-service-0.0.0-latest.tgz
   ```

 构建命令如下：

   ```bash
   bke build -f mainfests.yaml -t bke.tar.gz
   ```

#### 配置containerd的重定向 

安装节点使用的是containerd，其配置文件增加mirrors重定向，离线安装时镜像均来源于引导节点，

使用方法一：所有的镜像均来自引导节点的Registry，对于新增第三方镜像源就无需处理；

   ```bash
   [plugins."io.containerd.grpc.v1.cri".registry]
    [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
      [plugins."io.containerd.grpc.v1.cri".registry.mirrors."*"]
        endpoint = ["http://o.x.y.z:p"]
   ```

使用方法二：当前只配置用到的第三方镜像源；

```bash
[plugins."io.containerd.grpc.v1.cri".registry]
 [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
   [plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
     endpoint = ["http://o.x.y.z:p"]
```

注：后续有增量路由，目前不支持自动化更新，需要手动修改containerd的配置文件，然后重启containerd让配置生效。

```bash
[plugins."io.containerd.grpc.v1.cri".registry]
 [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
   [plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
     endpoint = ["http://o.x.y.z:p"]
   [plugins."io.containerd.grpc.v1.cri".registry.mirrors."fuyao.io"]  # 新增的镜像源
     endpoint = ["http://o.x.y.z:p"]
```

#### 组件增量补丁安装

构建离线增量制品包的详细流程如下：

1. 准备增量包的yaml配置文件

   ```yaml
   repos: # 离线环境部署所需的镜像
     - architecture:  # openfuyao ray扩展组件
         - amd64
         - arm64
       needDownload: true # 控制组件镜像是否需预下载，true-需下载，false-不下载
       subImages:
         - sourceRepo: harbor.openfuyao.com/openfuyao
           targetRepo: openfuyao
           images:
             - name: ray-website   # ray
               tag:
                 - latest
         - sourceRepo: docker.io
           targetRepo: /
           images:
             - name: busybox   # ray
               tag:
                 - latest
   rpms:
   debs: []
   files:
   charts: # chart包
     - address: https://harbor.openfuyao.com/chartrepo/openfuyao-catalog-pre/charts/
       files:
         - ray-package-0.0.0-latest.tgz
   ```
   
   

2. 执行构建指令，会得到tar.gz文件

   ```bash
   # 表示打增量包，patch参加就不会检查文件和镜像依赖项
   bke build patch -f manifets.yaml -t bke-patch4.0.tar.gz
   ```
   
   得到的目录如下：
   
   ```
   $ tree 
   └── bke-patch4.0
       ├── manifests.yaml
       └── volumes
           ├── charts.tar.gz
           └── image.tar.gz
   ```
   
   
   
3. 拷贝到离线引导节点，解压到任意目录（如/tmp/v2），除了镜像文件，其他文件直接拷贝到对应路径下即可，镜像文件需要使用bke同步到本地镜像仓

   ```bash
   # 镜像同步到Registry
   bke registry patch --source /tmp/v2/bke-patch4.0 --target 127.0.0.1:40443
   ```
