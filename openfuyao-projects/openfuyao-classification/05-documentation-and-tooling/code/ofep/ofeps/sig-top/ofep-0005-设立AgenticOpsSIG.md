# oFEP-0005：设立 Agentic Ops SIG

## 发布签核清单

openfuyao/ofep/sig-top/ofep-0005-设立AgenticOpsSIG.md

## 摘要

Agentic Ops SIG 面向承载 AI 负载的异构算力集群，构建开放、可靠、易用的智能体自主运维体系。
聚焦 **智能体自主运维**、**观测分析工具增强**、**运维经验沉淀与共建共享** 三大方向，
应对集群故障定位耗时长、经验分散沉淀复用难、技术迭代快导致运维成本高等核心挑战，
探索智能体闭环 AI 训推故障的运维新范式，推动开源社区在该领域的技术演进。

## 动机

AI 智能体加速落地千行百业，算力需求与训推规模指数级攀升，异构算力 AI Infra 运维面临严峻挑战：

1. **集群故障定位耗时长**：AI 训推故障横跨硬件、推理引擎与模型运行时多个层次，定位依赖资深 SRE 跨域排查，MTTR 长达数小时乃至天级，严重制约集群算力利用率。
2. **经验分散沉淀复用难**：硬件原厂、引擎社区、企业内部的运维经验散落于脚本、文档与个人隐性知识之中，缺乏统一沉淀与共建机制，对少数专家的依赖制约规模化运维。
3. **技术迭代快导致运维成本高**：硬件按代际跃迁，推理框架、训练范式与加速算子的迭代周期已压缩至周级，每次升级都引入新的故障模式与变更风险；传统基于规则与统计的 AIOps 难以同步适配，长期陷入"追赶模式"。

业界共识，智能体技术是运维技术由观测性迈向自主性的代际推动力。
既往与客户和伙伴的联创表明，智能体能够有效应对上述挑战。其长文融合理解能够聚合多源分散经验，消解技术迭代导致的知识割裂。
面向复杂故障场景，其自主推理的定位效率与分析深度已超越人工运维，初步验证了智能体运维范式的可行性。
我们提议成立 Agentic 运维特别兴趣小组 (Agentic Ops SIG)，面向异构算力 AI 基础设施构建智能体自主运维体系，通过开源社区共建，推动智能运维的技术演进与工程落地。

### 目标

构建面向异构算力 AI Infra 的可靠、开放、生产级智能体自主运维能力，达成以下量化目标：

- **智能体自主运维实现 MTTR 降低 50%+**：面向昇腾+鲲鹏 AI Infra，构建训推场景下的智能体自主调查能力，基于观测数据自主提出假设并查询验证，输出可回溯、可下钻至具体数据的根因结论，确保每一步推断均有证据链支撑。
- **观测分析工具增强缩减 90%+ 定位上下文**：基于既有观测基础设施，构建智能化工具增强富化原始度量数据，聚合碎片信号为结构化故障视图，为智能体提供高信息密度故障上下文。
- **运维经验沉淀与共建共享覆盖 95%+ 故障场景**：以智能体 Skill 作为运维经验的核心载体，将故障诊断定位策略封装为可复用资产，基于社区持续共建积累。同时构建 Skill 自动治理能力，通过智能去冗、去噪与冲突消解，确保 Skill 库在持续积累中始终保持高质量可用。

**聚焦场景**：聚焦 AI 训推故障自主诊断，覆盖集群硬件故障、训推作业中断、任务卡死劣化等典型问题。

### 非目标

- 模型推理能力（由 AI 推理 SIG 覆盖）
- 智能体通用框架（由开源社区 Agent 框架覆盖）
- 集群观测性工程：数据采集、数据存储、数据查询、数据可视化（由开源观测基础设施和 AI 推理 SIG 覆盖）

## 提案

### 技术方向与核心发力点

- **智能体自主运维**：面向主流 Agent 构建运维诊断拓展，注入故障诊断能力，使能AI自主完成从定位到修复的闭环。
- **观测分析工具增强**：基于既有观测基础设施，从工具增强与数据融合两个维度提升信号质量
  - 观测工具智能增强：在既有的指标查询、日志查询等观测工具中注入异常检测、模板抽取等智能分析能力，富化原始信号，提升 Agent 可消费的信息密度与信噪比。
  - 观测数据语义融合建模：将观测数据与训推作业拓扑融合为 Agent 可理解的运维语义。
- **运维经验沉淀与共建共享**：以智能体 Skill 为载体，从社区共建与自动治理两个维度构建可持续运维知识体系
  - 集群运维 Skill 社区建设：以社区运作机制驱动 Agent Skill 持续更新与积累，承载运维经验。
  - Skill 自动治理：构建自动化工具，实现 Skill 去冗、去噪与冲突消解，持续演进过程中保障高质量可用。

### 与 openFuyao 其他 SIG 能力协同

- 分布式推理套件运维支持：协同 AI 推理 SIG，为 Infernex 分布式推理套件提供原生智能体自主故障诊断能力。
- 推理框架观测数据复用：协同 AI 推理 SIG，复用Infernex Eagle-Eye内置指标、日志采集能力，避免重复建设观测数据采集链路。

### 与业界开源技术方案协同
- 基于 Claude Code、OpenCode、Pi、OpenClaw 等主流 Agent 的工具链拓展机制，注入故障诊断能力，复用其多轮推理与工具调用基础能力，不重复建设 Agent 运行时。
- 基于 Prometheus、OpenTelemetry、Grafana、Loki 等开源观测设施的查询接口，注入异常检测、模板抽取等智能分析能力，富化原始信号输出，不替代既有观测数据采集与存储链路。

### 路线图与里程碑

- **阶段1：（孵化期-2026Q3）**
  - obs-data-insight：提供高性能的指标异常检查，日志模版解析、数据特征提取等智能化工具，富化原始观测信号。
  - ops-skills-hub：将已积累的故障运维经验封装为 Skill 发布，建立社区共建与评审机制。
- **阶段2：（能力构建-2026Q4）**
  - ops-agent-extension：面向主流 Agent 构建运维诊断拓展，依托阶段1 的观测数据层与 Skill 库，打通故障诊断闭环。
- **阶段3：（优化期-2027Q1）**
  - obs-semantic-model：将观测数据与训推作业拓扑融合建模，构建 Agent 可理解的运维语义层。
  - skill-governor：实现 Skill 去冗、去噪与冲突消解，保障 Skill 库持续积累中的高质量可用。
  - obs-data-insight、ops-agent-extension、ops-skills-hub 持续迭代，联合生产级集群验证，MTTR 降低 50%+、缩减定位上下文 90%+、Skill 覆盖 95%+ 故障场景达标后并入社区发行版。

**注**：需进一步细化的部分（如 API 设计、性能指标）将在后续项目提案中展开，欢迎社区贡献者加入！
