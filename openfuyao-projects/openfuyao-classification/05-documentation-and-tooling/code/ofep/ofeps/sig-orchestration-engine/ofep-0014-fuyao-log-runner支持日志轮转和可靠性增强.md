上游社区的`kube-log-runner`功能单一，只提供日志重定向，本提案旨在对该机制进行功能扩展，提供字节级精细日志轮转；出现日志磁盘空间不足情况时，业务服务能够正常运行，不会出现退出情况；日志文件被删除时，可以自动恢复日志文件，保证日志正常输出。


## 动机
<!--
本节用于明确列出该oFEP的动机、目标和非目标。描述变更的重要性以及对用户的好处。
-->

目前kubernetes核心组件的日志均通过`kube-log-runner`完成对输出的重定向，日志轮转使用Linux `logrotate`管理，在实际运行中存在以下痛点：

- `logrotate`轮转周期根据配置固定，最小为每分钟执行一次，当日志生成速率很快时（e.g. 5MB/s)，无法及时轮转，输出日志文件过大，导致日志文件所在磁盘被写满，对应组件进程错误退出，服务中断，集群不可用；当出现磁盘空间满无法写入日志时，可以丢弃日志，需要确保服务不中断；
- `logrotate`只能设置转储文件个数，无法按照日志总大小对日志占用的磁盘空间配额进行管理；
- 当日志文件被误删时，日志文件无法自动恢复，会出现无法输出日志，造成日志丢失；
- 日志转储的压缩文件无法设置权限，无法按照安全要求进行权限定制；

### 目标
<!--
列出oFEP的具体目标。它想要达到什么目标？我们怎么知道这已经成功了？
-->
- 实现日志字节级精细轮转，当日志生成速率很快时（e.g. 5MB/s)，仍能实现轮转清理；
- 增强服务可靠性，在日志磁盘空间不足场景下，确保服务不中断，保障集群的可用性；
- 增强日志文件自恢复能力，日志误删后能够自动恢复；
- 对`kube-log-runner`的日志文件目录权限进行增强，可以按需对日志和转储文件进行权限控制；

#### 故事 1
业务长时间运行，日志文件过大，可能导致日志所在磁盘空间不足的情况；
当出现磁盘空间不足时：服务日志写入失败，服务能够继续正常运行，业务不中断。
当磁盘空间释放时：服务日志写入自动恢复，日志能够成功写入，在日志中记录故障发生时间、恢复时间。

#### 故事 2
在生产环境中，由于业务长期运行，会导致日志文件过大，无法进行有效的查看，当日志文件达到指定大小时，需要触发日志的自动轮转；为了保证磁盘空间，需要对于轮转的日志进行压缩和老化。

#### 故事 3
如果出现正在写入的日志文件被误删的情况，后续日志无法正常写入，会导致日志丢失，当日志文件不存在时，需要能够及时重新生成，保证日志能够正常输入。

### 实现方案

1. 上游社区`kube-log-runner`流程，将日志文件设置为子进程的outputStream，直接将业务的输出日志`stdout` 和 `stderr` 重定向到指定的日志文件，不支持日志的轮转、压缩；当日志文件所在磁盘空间不足的时候，会导致业务进程退出；当日志文件被删除后，不支持恢复，会导致日志丢失，如下：

#### 日志文件包装扩展

把日志文件包装为一个可扩展Writer，实现带后续处理的Write方法。

```go
type fileWrap struct { // 输出日志的包装
	target          *os.File
	filePath        string
	filePermissions uint32
	onErrFunc       []onErrFunc
	normalFunc      []normalFunc

	writtenBytes int
	writtenErr   error
}

func (f *fileWrap) Write(p []byte) (int, error) {
	f.writtenBytes, f.writtenErr = f.target.Write(p)
	if f.writtenErr == nil {
		for _, f := range f.normalFunc {
			f()
		}
	} else {
		for _, f := range f.onErrFunc {
			f()
		}
		f.writtenBytes = len(p)
	}
	return f.writtenBytes, f.writtenErr
}
```


#### 日志轮转、压缩功能
通过开关 `log-rotate-enable` 控制；通过单独协程来开启日志的轮转和压缩、老化功能。
轮转日志文件命名： <original-file-name>-<timestamp><file-extension>。
- <original-file-name>：原始日志文件的名称，不带文件扩展名。
- ` <timestamp> `：每个轮转文件的名称都会添加一个时间戳，根据其创建时间进行唯一标识。时间戳格式为“20250701-202324”。例如，2025 年 7 月 1 日20:23:24 ，创建的轮转日志名称将包含此时间戳。
- <file-extension>：文件的扩展名（例如 .gz）。

实现关键逻辑：轮转由单独协程实现不阻塞日志持续写入
```go
	stat, err := file.Stat()
	if err != nil {
		return nil, fmt.Errorf("failed to get file size with err: %v", err)
	}

	fileWrap := newFileWrap(file, w.FilePath, w.FilePermissions)
	var rotator *rotator
	if w.EnableRotate {
		rotator = newRotator(fileWrap, &w, stat) // 初始化轮转功能
		fileWrap.normalFunc = append(fileWrap.normalFunc, rotator.rotate)
	}


    func (r *rotator) rotate() {
            ...
            go r.startRotateLog() // 日志轮转协程
        }
    

    func (r *rotator) startRotateLog() {
        r.rotateLock.Lock()
        r.rotateCounting++ // 轮转请求计数
        r.rotateLock.Unlock()

        if r.rotateCounting != 1 { // 已经启动轮转，应对日志写入速率超高场景，确保同一时刻仅有一个轮转协程
            return
        }

        var err error
        defer r.afterRotateLog(err)
        err = r.rotateLogs()
        if err != nil {
            r.tryPrintErr(err)
        }
    }

```


#### 磁盘空间不足，业务不中断
当出现磁盘空间不足的时候，通过忽略错误输出的方式，保证业务进程不中断；通过开关 `log-ignore-nospace-error` 控制；

```go
	if w.IgnoreEnospc {
		var errHandler *errHandler
		if rotator != nil {
			updateCountFunc := func() {
				rotator.rotate()
			}
			errHandler = newErrHandler(fileWrap, updateCountFunc) // 当磁盘空间不足时，错误忽略处理Handler
		} else {
			errHandler = newErrHandler(fileWrap, nil)
		}

		fileWrap.onErrFunc = append(fileWrap.onErrFunc, errHandler.handleErr)
		fileWrap.normalFunc = append(fileWrap.normalFunc, errHandler.handleRecover)
	}

    
    func (e *errHandler) handleErr() { // 当出现磁盘空间不足的错误（ENOSPC）时，忽略错误信息，防止进程退出，同时记录错误出现的时间，当磁盘空间充足时，记录失败的时间信息；
        if errors.Is(e.writtenErr, syscall.ENOSPC) && !e.hasError {
            e.errTime = time.Now()
            e.hasError = true
            e.writtenErr = nil
        }

        if errors.Is(e.writtenErr, syscall.ENOSPC) {
            e.writtenErr = nil
        }
}

```

#### 日志文件删除，自动恢复功能
定时检测日志文件状态，当出现日志文件被删除的时候，重新创建日志文件，并记录日志恢复的信息；通过开关 `log-check-deleted-period` 控制；


```go
	if w.CheckLogDeletedPeriod > notCheck {
		var checkLogFileHandler *checkLogFileHandler
		if rotator != nil {
			updateTargetFunc := func(file *os.File, writtenBytes int64) {
				rotator.target = file
				rotator.counter = writtenBytes
			}
			checkLogFileHandler = newCheckLogFileHandler(fileWrap, &w, updateTargetFunc)
		} else {
			checkLogFileHandler = newCheckLogFileHandler(fileWrap, &w, nil)
		}
		go checkLogFileHandler.periodicallyCheckIfLogFileIsDeleted() // 启动独立的协程来定时判断，如果发现日志文件被删除，自动恢复出日志文件，并记录恢复信息。
	}

    
    func (c *checkLogFileHandler) periodicallyCheckIfLogFileIsDeleted() { // 定期检测日志文件，当文件不存在时候，进行日志文件恢复
        retryPeriod := time.Duration(c.checkLogDeletedPeriod) * time.Second
        timer := time.NewTimer(retryPeriod)
        for {
            select {
            case <-timer.C:
            }
            _, err := os.Stat(c.filePath)
            if err != nil && os.IsNotExist(err) {
                c.installNewLogFile()
            }
            timer.Reset(retryPeriod)
        }
    }

```
